# 历史会话归档：读写规则

这份文档只说明历史会话 ZIP 是怎么读、怎么写、哪些内容能还原、哪些内容故意不还原。字段定义在 [format.ts](./format.ts)，校验规则在 [schema.ts](./schema.ts)，入口在 [../backup.ts](../backup.ts)。

归档格式沿用 DeepSeek 的 `export_format_version: 3`，导出文件名是 `deepseek_data-日期.zip`。这不是一个新的私有格式；改的是导入后的本地消息模型和合并策略。

## 文件结构

```text
manifest.json                                      格式版本，必须是第一个条目
chat_sessions/{session_id}.json                    会话与消息树
chat_session_index.json                            会话索引
chat_sessions/{session_id}_files/{file_id}_{file_name}  图片原件
```

导入时也接受“会话 JSON 和该会话图片交错排列、索引在末尾”的顺序。`user.json` 可以出现在 manifest 和会话之间，导入会略过；本仓库不导出账号信息。图片按 `FILE.export_path` 匹配。

可选字段可以缺省。时间必须是 `Z` 结尾的 UTC，可以带小数秒。校验后只保留已定义字段，未知类型或无法解析的内容片段直接丢弃；容器和元数据不合法仍然整包失败。

## 导入

1. 用户确认导入方式后，后台线程先读第一个条目检查格式和版本，再逐条解析会话，分批写入 IndexedDB 的暂存区。上一批落盘时解析下一批；特别长的会话单独处理。
2. **合并模式（默认）**：完整校验通过后暂停写入和生成，对重叠会话按消息树做“导出再导入不改变语义”的深度合并。只写新增和有变化的会话与新附件；没有变化的会话不落盘；未完成或错误的回复，如果另一份快照更完整，就地升级；真正的分叉挂成兄弟分支。草稿、当前打开会话和置顶取并集。
3. **替换模式**：先校验索引、消息树和 ZIP，再停止生成并暂时禁止修改会话。一个事务切换当前存储指针，并标记旧存储待清理；旧数据随后分批删除，应用关闭后下次启动继续清。手动删除全部历史时，同一个事务也会清空原存储。
4. 校验失败时，原有记录和正在生成的回答都保留。提交失败也保留原记录。中断留下的暂存区会在下次导入前清理，不混进正式数据。
5. 读取时按归档字节显示进度和剩余时间估算。整理附件、合并历史和替换历史各有独立状态。

消息树靠 `id` / `parent_id` 还原。父消息 ID 必须小于子消息 ID，角色交替，根节点是提问。`current_message_id` 决定当前分支；其他节点默认选中 ID 最大的子消息。缺失原件的附件保留文件名和大小，但不进入后续请求；有原件的导入图片在第一次用于请求时才上传。

导入时一次性转换成正式消息，正文、思考用时、模板标识、工具结果和阅读链接签名都写进本地消息字段，不保留原始消息副本。展示、请求和导出都读这一份消息。只支持当前数据格式，不提供旧数据库迁移。

## 消息树、状态与请求

- 展示提问、正文、思考、附件，以及搜索、打开网页、页内查找步骤。搜索状态和查找词存在时参与展示；`READ_LINK` 有合法 URL 时展示链接与标题，只有签名的记录留在请求上下文里。展示链接只接受 HTTP / HTTPS。
- `TIP`、`CONTENT_RISK`、`PARTIAL_FILE_READ`、`TOOL_IMAGE_SEARCH` 等没有对应展示的内容直接丢弃，不补占位符。工具分组等没有映射到本地消息的元数据也不保留。完整规则在 [toLocal.ts](./toLocal.ts)。
- `FINISHED` 转成已完成；`INCOMPLETE` / `WIP` 转成已停止；`FAILED` / `CONTEXT_LENGTH_EXCEEDED` / `TIMEOUT` 转成错误；`CONTENT_FILTER` 转成拒绝。思考与搜索开关保存在回复里。
- 错误回复用红字和感叹号提示，正文和思考分开显示。拒绝和其他非错误模板使用正文样式；拒绝回复丢弃普通正文和思考，可以复制模板，不能重新生成。模板单独展示，不混进工具步骤前的说明。
- 错误和模板回复留在消息树里，但所在轮次不进入后续请求上下文。
- 已完成或已停止、有正文、不是拒绝、也不含服务端模板的回复，可以进入上下文。
- 请求从当前消息回传正文，以及 `READ_LINK` 工具块里的签名、URL 和标题，供服务端恢复网页上下文。历史思考和其他工具块不回传，详见 [../reply.ts](../reply.ts)。

## 导出

导出完整消息树和当前分支，写出本地置顶状态 `pinned`，只附带本地存在的图片原件；非图片附件只有元数据。所有消息都从当前正式消息转成归档片段，包含搜索状态、页内查找词、模板正文、思考用时，以及成功阅读链接结果的签名、URL 和标题。导入后再修改的内容、状态和附件，以当前值为准，不回写原始归档。具体映射见 [toArchive.ts](./toArchive.ts)。

本地错误和拒绝提示按导出时的界面语言写进 `TEMPLATE_RESPONSE`，导入后保留文案，不参与上下文。正常空回复和达到长度上限的回复不补造提示；已有模板原样保留，重复导出不会重复追加。

导出开始时先保留列表和已加载会话的内存快照，没打开的会话再逐条从 IndexedDB 读，不写界面详情缓存。读取期间会话被删除、拿不到内容时，整次导出失败。导出标题使用开始时的列表快照。

归档不保存 API Key 和应用设置，也不能完整恢复本地运行状态。下面这些不会保留：

- 正文引用角标
- 非图片附件的原件
- 模型与思考签名
- 原工具调用 ID
- 结构化错误信息（类型、状态码、重试操作等）
- 用量明细
- 非当前分支的选择
- `latestReminder` 快照

新提问的快照按当前设置生成。

## ZIP 与限制

| 文件 | 职责 |
| --- | --- |
| [format.ts](./format.ts)、[schema.ts](./schema.ts) | 归档类型与字段校验 |
| [toLocal.ts](./toLocal.ts)、[toArchive.ts](./toArchive.ts) | 归档与本地消息互相转换 |
| [mergeSessions.ts](./mergeSessions.ts) | 同会话消息树语义深度合并 |
| [importArchive.ts](./importArchive.ts)、[exportArchive.ts](./exportArchive.ts) | 条目读取、暂存与归档组装 |
| [zipReader.ts](./zipReader.ts)、[zipWriter.ts](./zipWriter.ts) | ZIP 读写、路径、大小与 CRC 校验 |
| [../backup.ts](../backup.ts) | 导入导出入口与串行队列 |

支持单卷 ZIP32 的 STORE / DEFLATE，导出用 STORE。不支持 ZIP64、加密、分卷和非 UTF-8 的非 ASCII 文件名。条目名统一按 NFC 比较。没有额外的业务大小上限，但受 ZIP32 容量和浏览器内存限制；导出会生成完整的下载 Blob。
