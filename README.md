## 4. 构建、安装与迁移

### 4.1 迁移旧版数据

`0.9.0` 使用独立包名，Android 将其与旧版 `io.github.lijiahua1024.dsreplica` 视为两款应用。两版可并存安装，但不共享应用数据。

迁移步骤：

1. 在旧版执行「导出所有历史对话」。
2. 在 DeepSaga 执行「导入历史对话」，选择旧版导出的 ZIP。
3. 重新填写 API Key。备份不包含 API Key。
4. 检查角色卡、世界书、场景与记忆是否完整。旧格式存在字段缺失或无法定位的条目时，导入会跳过并计数，不保证全部恢复。

历史对话 ZIP、单会话包、设定存档和记忆归档继续使用原格式标识，DeepSaga 可读取旧版导出的包。内部 `replica:` 存储键保持不变，用于兼容既有数据。

### 4.2 构建

前端：

```bash
pnpm install
pnpm type
pnpm lint
pnpm build
```

构建产物输出到 `dist/`。

Android：

```bash
cd android
./gradlew assembleRelease
```

当前工程配置为 Gradle 9.7.1、AGP 9.4.0、compileSdk 37、minSdk 29。环境版本不一致时，由构建者调整 `android/app/build.gradle` 并自行验证。

仓库不附带签名文件。构建者必须自行生成并保管签名密钥；签名文件、Keystore 密码和发布凭据禁止提交到仓库。

### 4.3 首次使用

1. 在设置页填写 API Key、接口地址和模型名。
2. 选择 Chat Completions、Responses、Anthropic 或自定义兼容网关。
3. 发送一条普通消息，确认接口返回文本正常。
4. 需要角色扮演时，启用一张角色卡、填写基础档案或写入自定义提示词。
5. 长对话前检查「Token 与费用」页，确认当前开启的消耗项。
6. 导出重要会话、角色卡、世界书和记忆。卸载应用会删除本地数据。

## 5. 功能与行为边界

### 5.1 接口与请求

- 支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和自定义兼容网关。
- 支持 Ollama、LM Studio、vLLM、LocalAI 等本地兼容端点。
- 支持模型名、接口地址、API Key、自定义请求头和绘图模型配置。
- 自定义请求头支持多行 `Key: Value` 与 JSON 对象；同名头覆盖内置值，包括 `Authorization`。
- 自定义接口下，`system` 不整体置空：角色卡或基础档案、表达提示词和固定演出规则进入 `system`；记忆、场景和当前轮次世界书接在当前 user 消息末尾。
- 不同网关对图片、工具调用、搜索、`reasoning`、`safety_check` 和 `latest_reminder` 的支持不一致。网关拒绝未知字段时，由使用者关闭对应字段后重试。
- 本地模型的上下文长度、显存和并发能力由使用者本机配置决定。

### 5.2 会话、分组与本地数据

- 会话支持新建、重命名、置顶、分组、归档、批量移动、复制、导出和删除。
- 会话列表按时间分组；存在角色会话时，时间组内再拆分普通聊天与角色子组。
- 时间标签在列表内吸顶，滚动时始终停在可见区顶部；长按时间标签可整组删除，删除前必须二次确认，组内含角色会话时可只删角色会话，也可先把整组归档。
- 多选支持全选、取消全选，以及先点首条再点末条的范围选择；桌面端按住 `Shift` 点击也能直接选中连续区间。
- `30天` 组只显示天数，不再附加“近一个月”后缀。
- 用量明细只保留输入、输出、缓存命中、未命中和命中率，不再显示“模式切换 · 首轮缓存重建”标签。
- 支持从任意消息创建分支。分支继承分叉点之前的上下文、记忆和场景，不继承分叉点之后的内容。
- 支持重新生成并保留旧回答版本、编辑用户消息、编辑模型回复、删除单条消息和删除会话。
- 本地持久化覆盖会话、分支、消息版本、草稿、附件引用、基础档案、角色卡、世界书、场景、记忆、设置与备份元数据。
- 自动备份写入 `Download/DeepSaga/自动备份`，先写临时文件，核对大小并校验 ZIP 后才发布；默认保留最近 5 份完整备份。
- 自动备份按本机数据版本去重：完整备份成功后，没有新增对话、消息、角色卡、世界书、记忆或设置时不重复写盘；检测到新数据后才恢复按间隔备份。手动“立即备份”不受此限制。
- 导入历史归档前校验 ZIP 结构、条目 CRC、会话 JSON、消息分支和完整性摘要。新导出的每个会话都带消息数量与内容摘要；JSON 仍可解析但消息被截断或正文被改写时，会按“消息数量不一致”或“消息内容与校验值不一致”列出对话标题并跳过。没有摘要的旧备份继续按结构与分支校验导入。单个会话 JSON、分支、附件或 ZIP 条目损坏时同样逐对话跳过；只有 manifest 缺失、版本不兼容、中央目录不可读或没有任何可用对话时才整体失败。
- 导出历史归档时显示分阶段进度：整理会话（已处理数量）、压缩打包（字节进度）与保存文件，长列表和大量图片下也能看到当前阶段。
- 启动遮罩等会话首屏真正绘制完成后再淡出；淡出期间内容已就位，不再出现空白页一闪。用户气泡与 AI 正文共用上弹入场，系统开启“减少动态效果”时自动关闭。
- 分支、重新生成和导入都会改变后续请求上下文；操作前应确认影响范围。

### 5.3 角色系统

- 全局同一时间只启用一张角色卡。会话可绑定独立角色，绑定优先于全局开关。
- 人物层固定为「一张角色卡 → 一份基础档案 → 一条轻量身份行」三选一，不叠加冲突身份。
- 基础档案包含 32 项，按基本档案、身体与生活、性格与边界、剧情与表达四组排列。
- 角色卡覆盖固定参数、生活细节、性格边界、题材玩法、关系、经历、情景、目标、说话方式、口癖、秘密、补充设定、开场参考、对白示例和卡内系统指令。
- 角色正文固定以第一人称「我」叙述自己的动作、感官和心理。第三人称代词只用于他人转述，禁止把角色写成第三人称旁白。
- 支持角色卡搜索、分组、单卡收起、编辑器分组折叠和完成度提示。
- 支持导入 Character Card V2/V3、TavernAI 与 PNG chara。
- 每张卡可填写来源标注与作者 / 作品主页链接。链接只接受 `http` / `https`，仅用于卡片展示，不进入 `system`；找不到作者主页时填作品页或其他公开来源文档，不伪造作者主页。
- 角色卡页固定显示「来源与导入声明」：二创、游戏、动漫、小说和他人原创设定的版权归原作者，导入前需确认使用与分享权限；商用、公开发布或再分发需另行取得授权。
- 内置「大肥鱼」「鲸鱼娘」头像，以及欢迎页、API Key 设置页的大肥鱼插图，使用社区二创原图，不使用上游蓝色鲸鱼。角色原型为「溟月」（上善无形，<https://space.bilibili.com/4456176>），女仆装与 DeepSeek 元素二创由 ZipZipPipe 完成（<https://space.bilibili.com/4168597>），大肥鱼头像由 SlimeNull 绘制（<https://space.bilibili.com/441842015>）；内置卡作者入口指向原型作者上善无形的 B 站主页。具体图片作者、文件与许可见 [assets/fanart/SOURCES.md](assets/fanart/SOURCES.md)。
- 二创图片按 CC BY-NC-SA 4.0 使用：必须署名、禁止商业使用、修改后的图片须以相同协议共享。应用代码的 GPL-3.0 不覆盖这些图片。
- 世界书最多 100 条，支持关键词或正则命中、常驻条目、按角色绑定、单轮预算、最近发言或整段历史扫描、避触词和三级可信度。
- 场景覆盖时间、地点、天气、穿着、心情、关系阶段、氛围与感官、在场人物、目标、冲突悬念和关键物件；支持手填与按轮自动提取。
- 表达提示词支持 `{{user}}` 和 `{{char}}` 占位符。
- 默认不启用角色扮演。清空表达提示词时回到普通 AI 助手，并停用角色卡、基础档案、身份行、场景、世界书与角色记忆。
- 空提示词或默认提示词开启「出戏压制」时，进入基础角色扮演，默认预设为大学时期青梅竹马「沈知夏」。关闭后回到普通 AI 助手。设置页提供自定义预设开关与文本框；自定义文本非空时整段替换内置预设，关闭后立即回内置但保留文本。
- 自定义提示词不受「出戏压制」接管，仅在末尾追加来源说明。

### 5.4 长期记忆

- 记忆分为角色记忆与普通记忆两个独立池，各自有卡片上限、字数上限和注入开关。
- 角色记忆分完整回合、重要场景、关键事实三层。完整回合保留双方原话；重要场景摘出地点、人物、事件、气氛和关键细节；关键事实保存姓名、称呼、关系、喜好、承诺和边界。
- 角色池自动整轮按“玩家名字（玩家本人）”和“角色名字（角色本人）”拆成两张卡，正文不再统一写“用户”；没填名字或名字仍是占位值时回退为“玩家 / 角色”及归属标签。旧卡没有记录名字时，面板按当前玩家名与角色名补显。
- 普通记忆分对话、代码、用户原话、AI 原话四类，按关键词检索。
- 显示名为 AI / DeepSeek 时写入普通记忆；显示名为角色卡名或手写档案名时写入角色记忆，并暂停普通记忆写入与注入。
- 记忆按会话和分支隔离。新建会话不会继承旧会话记忆；分叉会继承分叉点之前的卡片。
- 角色记忆支持关闭、整轮记录、自动提炼三种模式。自动提炼额外发起一次合并请求，并逐条标注 `[玩家本人]` / `[角色本人]` / `[共同经历]`。
- 自动提炼只能替换普通自动回合卡。手动卡、置顶卡、重要场景和关键事实不参与替换，也不参与自动归档。
- 注入顺序为手动记录 → 置顶 → 重要场景 → 关键事实 → 最近回合 → 相关旧卡。
- 支持时间锚点召回、记忆面板分类筛选、手动补卡、置顶、编辑、删除、双击跳转、整段保存和分类导入导出。
- 记忆是模型上下文，不是数据库事实。模型可能忽略、误用、重复或混淆记忆内容。

### 5.5 连续语音通话

- 支持 VAD 断句、ASR 转写、流式 TTS、播放中插话打断。
- 无活动会话时可直接开麦；首条转写会创建会话并生成标题。
- WebView 采集被系统拦截时，尝试切换原生 `AudioRecord`；原生通道中断后最多重建两次。
- 提供系统录音通道自检，用于区分权限问题与采集问题。
- 语音链路依赖 WebView、麦克风权限、音频焦点和 Android 版本。系统权限拒绝、后台限制或录音通道占用会导致失败。
- 连续语音通话产生文本模型与 TTS 费用。计费由服务商决定。

### 5.6 个性化、Token 与诊断

- 支持用户头像、用户名、角色头像、角色名、头像大小、头像形状、独白置灰、主题色、气泡样式、布局、字体大小和消息间距。
- 个性化设置只影响本机显示，不进入请求，不随设定存档导出。
- Token 统计读取上游返回的 `usage` 字段，记录输入、输出、缓存命中与未命中。
- 应用不计算价格，不读取余额，不代表服务商账单。余额、单价、扣费和发票以服务商后台为准。
- 页面集中列出九类会增加消耗的开关：深度思考、智能搜索、世界书注入、长期记忆、场景自动更新、记忆自动提炼、自动压缩、自动标题、上下文提醒。
- 100 万以下显示完整数字并带千分位；达到 100 万才缩写为 `1M` / `1.1M`。
- 缓存命中由上游按完整请求前缀判断。切换模型、角色卡、分支、开关状态，编辑历史，触发压缩或 `latest_reminder` 变化，均会导致前缀改变。
- 诊断日志用于排查白屏、卡顿、请求失败和权限问题。日志可能包含请求元信息，对外提供前必须检查是否含 Key、地址或聊天内容。

### 5.7 安全审核与拒答

- `safety_check` 默认开启。开启时请求体携带该字段，由服务端按其规则检查并过滤内容。
- `safety_check` 是应用层请求字段控制，不是本地内容过滤器；不替代上游服务商或网关的底层审查。
- 关闭 `safety_check` 仅表示本应用不再附加该字段。服务商、网关或平台仍可能执行审核。
- 服务端拒答时，消息标记为 `refusal`。可配置是否保留已下发正文、被拒轮次是否进入上下文，以及拒答话术。
- 本地关键词拒答只检查当前输入文本，命中后直接返回话术，不调用接口。该功能只做字面匹配，不识别语义、谐音或变体，不替代完整内容审核。
- 开启或关闭审核开关不改变使用者对输入内容、模型输出、传播行为和实际后果的责任。
