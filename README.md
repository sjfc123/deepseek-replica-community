## 2. 架构与代码结构现状（请卡顿敏感的使用者先读）

### 2.1 规模与构成

- 前端源码约 **219** 个 TypeScript / TSX 文件、约 **64,700** 行，集中在 `src/`；无独立后端工程。
- 状态管理使用 **7 个 zustand store**：会话主状态、设置、余额、草稿、附件、朗读、语音通话。
- 前端**未使用路由库**，单页内切换视图；**未配置组件级 / 端到端测试框架**，回归能力来自仓库内的 Node 校验脚本。

### 2.2 已知结构性债务

本仓库由多个迭代版本堆叠形成，保留了历史分支判断、重复条件、本地兜底、局部硬编码和未完成抽象。代码中存在大量粗糙实现，可按通常所说的“屎山代码”理解；它不是经过企业级重构的工程样板，不代表清晰分层、完整领域建模或长期可维护性。当前可追踪的结构性问题包括：

- **巨型全局会话状态**：`src/services/chat/store.ts` 约 **3,759** 行，被约 **41** 个文件引用；会话、消息、分支、草稿、附件、身份、记忆、请求与流式状态耦合在同一 store 中。任何一处改动都可能牵动整表更新，是长会话与流式渲染卡顿的主要结构性来源。
- **设置状态集中过载**：`src/services/settings.ts` 约 **2,046** 行，被约 **39** 个文件引用；设置、Key、个性化与部分运行时状态混在一起。
- **超大组件文件**：`src/components/settings/AndroidSettings.tsx` 约 **5,704** 行、`src/components/settings/RoleplayPanel.tsx` 约 **2,777** 行；单文件承载多组分区、表单、弹层与状态读写，解析与更新成本高。
- **非虚拟列表**：消息列表靠可见窗口封顶（首屏 40、向上每次 +20、上限 80）控制工作集，并不是真正的虚拟列表；缺少上下 spacer 与视口附近按需挂载，滚动锚点、搜索跳转、版本切换、长按多选四条链路未做虚拟化。
- **Worker 可回退主线程**：Markdown 解析、历史导入优先走 Worker；老 WebView 或 Worker 初始化失败时回退主线程，ZIP 解压、CRC 校验与 AST 解析会阻塞主线程。
- **测试底座薄弱**：无组件单测与 E2E 覆盖，回归脚本只校验仓库内规则；通过脚本不等于真机、长会话、模型与网关组合下无缺陷。
- **耦合与硬编码**：提示词拼装、身份判定、记忆路由、界面文案与部分配置存在局部硬编码和重复分支；二次开发前必须通读请求装配、状态持久化、角色卡、记忆、备份与设置链路。

### 2.3 哪些场景更容易卡顿或出问题

在以下条件叠加时，出现卡顿、滚动抖动、白屏、闪退、内存压力或长请求响应变慢的概率更高：

- 低内存设备、老旧或被厂商裁剪的 WebView 内核、折叠屏 / 分屏 / 悬浮窗等特殊形态；
- 超长会话、大量历史消息、超大角色卡、庞大世界书或大量记忆卡；
- 流式输出超长回复、Markdown / 代码块 / 表格 / 公式 / 图表密集；
- 导入包含大量图片或附件的历史备份；
- 网关返回的 `usage`、缓存或工具字段异常，触发前端降级与重复计算。

### 2.4 已做的减载与残余风险

已落地的减载措施包括：可见消息窗口封顶、Markdown 解析与历史导入优先 Worker、重覆盖层（设置面板、语音浮层、历史结算弹窗）按需懒加载、流式 Markdown 按渲染耗时节流、历史按批次结算、诊断采样在非 Android 环境降载。这些只能**降低**卡顿概率，不能把结构性债务消除，也不保证在弱机或长会话下流畅。

未合入的性能改造（真正虚拟列表、会话结构版本号与增量持久化、流式状态独立切片、诊断分级采样自动上报）见 [PERFORMANCE-AUDIT.md](PERFORMANCE-AUDIT.md) 第 9 节。**本仓库不再跟进这些改造。**

### 2.5 自助要求

二次开发、公开分发、商业使用或接入敏感数据前，必须先完成代码审计、补充测试、隔离凭据，并由构建者自行验证兼容性与安全性。若你已经遇到卡顿：

- 优先自行拆解巨型 store 与超大组件、引入真正的虚拟列表、把流式与持久化状态切片；
- 在目标机型上复现并定位主线程长任务、DOM 节点增长、监听 / 定时器 / 观察者泄漏与持久化重复写入；
- 本仓库不提供上述重构、问题定位或兼容修复。不要把本仓库的目录组织、状态写法、提示词拼装或组件耦合方式视为最佳实践。

## 3. 功能概览

功能以当前界面和源码为准，完整入口与自测边界见 [FEATURE-GUIDE.md](FEATURE-GUIDE.md)。要点如下：

### 3.1 对话与接口

- 支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 与自定义兼容网关；可接入 Ollama、LM Studio、vLLM、LocalAI 等 OpenAI 兼容服务。
- 可配置接口地址、模型名、API Key、自定义请求头、采样参数、温度、Top P、最大输出 Token。
- 支持流式回复、消息重生成、编辑用户消息、编辑模型回复、删除单条消息、消息版本保留。
- 支持图片、文件、PDF 等附件；附件能否发送由所选网关的文件能力决定。
- 深度思考、智能搜索与安全审核字段是否生效，取决于网关是否接受对应请求字段。

### 3.2 会话与本地数据

- 会话支持新建、重命名、置顶、分组、归档、批量移动、复制、导出和删除；多选支持全选、取消全选与首尾范围选择。
- 支持从任意消息创建分支；分支继承分叉点之前的上下文、记忆和场景，不继承分叉点之后的内容。
- 会话、分支、消息版本、草稿、附件引用、角色卡、世界书、场景、记忆、设置与备份元数据保存在本机。
- 支持历史会话 ZIP、单会话包、设定存档和记忆归档导入导出；导入校验 ZIP 结构、条目 CRC、会话 JSON、消息分支与完整性摘要。自动备份先写临时文件，核对大小并校验 ZIP 后发布，默认保留最近 5 份完整备份。

### 3.3 角色扮演

- 全局同一时间只启用一张角色卡；会话可绑定独立角色，绑定优先于全局开关。人物层为角色卡、基础档案、轻量身份行三选一，不叠加冲突身份。
- 角色卡包含固定参数、生活细节、性格边界、题材玩法、关系、经历、情景、目标、说话方式、口癖、秘密、补充设定、开场参考、对白示例和卡内指令。
- 支持 Character Card V2/V3、TavernAI、PNG chara 导入；世界书支持关键词或正则命中、常驻条目、按角色绑定、单轮预算、最近发言或整段历史扫描、避触词与可信度分层。
- 官方助手人格是独立开关；开启时不叠入手写系统提示词、自定义预设或基础扮演。会话绑定的自定义角色扮演预设按所选范围作为同级身份来源生效。

### 3.4 长期记忆

- 记忆分为角色记忆与普通记忆两个独立池，分别限制卡片数量与字符预算；角色记忆分完整回合、重要场景、关键事实三层，普通记忆按对话、代码、用户原话、AI 原话四类关键词检索。
- 记忆按会话和分支隔离；新建会话不继承旧会话记忆，分支继承分叉点之前的卡片。
- 记忆进入模型上下文，不是数据库事实；模型可能忽略、误用、重复或混淆记忆内容。

### 3.5 个性化、用量与语音

- 支持头像、用户名、角色头像 / 角色名、头像大小与形状、主题色、气泡样式、布局、字体大小、消息间距；个性化只影响本机显示，不进入请求，不随设定存档导出。
- Token 统计读取上游返回的 `usage`；余额优先请求官方 `/user/balance`，网关不支持或网络失败时进入降级态，不按本地费率推算账单。
- 语音链路依赖 WebView、麦克风权限、音频焦点与 Android 版本；权限拒绝、后台限制或录音通道占用会导致失败。

## 4. 构建、安装与迁移

### 4.1 前端构建

```bash
pnpm install
pnpm type
pnpm lint
pnpm build
```

构建产物输出到 `dist/`，由 Android 壳在 WebView 中加载；仓库不附带独立的网页端运行入口或静态托管服务。

### 4.2 Android 构建

```bash
cd android
./gradlew assembleRelease
```

工程基线为 Gradle 9.7.1、AGP 9.4.0、minSdk 29、targetSdk 36；`compileSdk` 跟随本机已安装平台。构建者必须自行生成并保管签名密钥；签名文件、Keystore 密码和发布凭据禁止提交仓库。

### 4.3 旧版数据迁移

`0.9.0` 使用独立包名，Android 将其与旧版 `io.github.lijiahua1024.dsreplica` 视为两款应用，两版可并存安装，但不共享应用数据。

1. 在旧版执行“导出所有历史对话”。
2. 在 DeepSaga 执行“导入历史对话”，选择旧版导出的 ZIP。
3. 重新填写 API Key；备份不包含 API Key。
4. 检查角色卡、世界书、场景与记忆是否完整。旧格式字段缺失或无法定位的条目会被排除并计数，不保证全部恢复。

内部 `replica:` 存储键保持不变，用于兼容既有数据。

## 5. 数据与隐私

- 无账号体系，无中转服务器，无开发者数据收集。
- API Key 由使用者填写，Android 侧通过系统 Keystore 加密存储；会话、角色卡、世界书、场景、记忆和附件保存在设备本地。
- 请求只发往使用者配置的接口地址；网关、服务商和网络环境的记录方式不在本仓库控制范围内。
- 导出备份不包含 API Key，但可能包含聊天记录、角色卡、设定和图片；对外发送前必须检查内容。
- 卸载应用、清理应用数据、更换设备、设备损坏或备份损坏会删除本地数据，使用者必须自行备份并先导出再迁移。
- 清理应用数据、更换设备不会自动迁移；`promptLocks` 冻结快照等设置层数据是否被跨设备备份 / 导入导出完整携带，见 [SYSTEM-PROMPT-PIPELINE.md](SYSTEM-PROMPT-PIPELINE.md) 与 [DISCLAIMER.md](DISCLAIMER.md)。

## 6. 已知技术边界

- **设备与 WebView**：未覆盖全部厂商 ROM、Android 版本、WebView 内核、折叠屏、分屏、悬浮窗和低内存设备。白屏、闪退、权限拒绝和录音通道差异必须在目标设备复现后处理。
- **网关差异**：不同网关对图片、工具调用、搜索、推理参数、缓存字段和自定义协议支持不一致。部分 400、空回复、余额不可用或计费异常来自上游，前端无法单方面修复。
- **模型输出**：角色一致性、称呼、语气、记忆引用、功能推荐和长文结构取决于模型能力、采样参数、上下文长度、角色卡质量和历史完整性。现有提示词约束只降低跳脱概率，不保证模型一定遵守。
- **规则清洗**：思考展示层按固定规则切除残留计划句和态度话术，不是语义理解；新措辞可能漏过，旧词也可能误伤人物原话。
- **长上下文**：超长会话、大量记忆卡、超大角色卡和世界书会触发压缩、截断、渲染卡顿或内存压力；现有配额是保护机制，不是无限容量承诺。
- **历史导入**：历史版本、第三方修改版和手工编辑包可能存在字段缺失、ID 冲突或格式不一致。无完整性摘要的旧备份只能校验结构与分支，无法发现字段合法但内容被截断或改写的情况。
- **缓存命中**：命中由上游按完整前缀判断；切换模型、角色卡、分支、开关状态、编辑历史、触发压缩或提醒变化都会改变前缀。诊断只定位可能断点，不保证命中率。
- **提示词绑定**：当前实现为单条手写系统提示词绑定一组会话；多段独立提示词分别绑定不同会话的模型不在本轮范围内。
- **回归范围**：仓库内回归脚本覆盖提示词、检索意图、角色、故事、备份、数据、附件、记忆、分组、建议、缓存、余额与主题等链路；脚本通过不等于所有真实设备、模型和对话场景无缺陷。
- **版本检查入口**：设置内「检查更新」读取 main 分支 `package.json` 与本地版本比较，只查询、不自动下载或覆盖安装。仓库闭关后版本冻结为 `1.0.0`，该入口不会再收到后续版本提示；历史版本清单、下载链接与更新链由使用者自行判断，仓库不维护更新通道。
