## 4. 构建、安装与迁移

### 4.1 迁移旧版数据

`0.9.0` 使用独立包名，Android 将其与旧版 `io.github.lijiahua1024.dsreplica` 视为两款应用。两版可并存安装，但不共享应用数据。

迁移步骤：

1. 在旧版执行「导出所有历史对话」。
2. 在 DeepSaga 执行「导入历史对话」，选择旧版导出的 ZIP。
3. 重新填写 API Key。备份不包含 API Key。
4. 检查角色卡、世界书、场景与记忆是否完整。旧格式存在字段缺失或无法定位的条目时，导入会排除并计数，不保证全部恢复。

历史对话 ZIP、单会话包、设定存档和记忆归档继续使用原格式标识，DeepSaga 可读取旧版导出的包。内部 `replica:` 存储键保持不变，用于兼容既有数据。

### 4.2 构建

前端：

```bash
pnpm install
pnpm type
pnpm lint
pnpm build
```

构建产物输出到 `dist/`。

Android：

```bash
cd android
./gradlew assembleRelease
```

工程基线为 Gradle 9.7.1、AGP 9.4.0、minSdk 29、targetSdk 36；`compileSdk` 跟随本机已安装平台。本次构建环境的公网 SDK 仓库只提供到 android-36，故以 36 编译，源码未使用 API 37 专属接口。环境版本不一致时，由构建者调整 `android/app/build.gradle` 并自行验证。

仓库不附带签名文件。构建者必须自行生成并保管签名密钥；签名文件、Keystore 密码和发布凭据禁止提交到仓库。

### 4.3 首次使用

1. 在设置页填写 API Key、接口地址和模型名。
2. 选择 Chat Completions、Responses、Anthropic 或自定义兼容网关。
3. 发送一条普通消息，确认接口返回文本正常。
4. 需要角色扮演时，启用一张角色卡、填写基础档案或写入自定义提示词。
5. 长对话前检查「Token 与费用」页，确认当前开启的消耗项。
6. 导出重要会话、角色卡、世界书和记忆。卸载应用会删除本地数据。

## 5. 功能与行为边界

完整功能入口、设置分区、近期重构/优化/修复记录与自测边界见 [FEATURE-GUIDE.md](FEATURE-GUIDE.md)；源码交付与责任声明见 [DISCLAIMER.md](DISCLAIMER.md)。

### 5.1 接口与请求

- 支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和自定义兼容网关。
- 支持 Ollama、LM Studio、vLLM、LocalAI 等本地兼容端点。
- 支持模型名、接口地址、API Key、自定义请求头和绘图模型配置。
- 自定义请求头支持多行 `Key: Value` 与 JSON 对象；同名头覆盖内置值，包括 `Authorization`。
- 自定义接口下，`system` 不整体置空：角色卡或基础档案、表达提示词和固定演出规则进入 `system`；记忆、场景和当前轮次世界书接在当前 user 消息末尾。
- 不同网关对图片、工具调用、搜索、`reasoning`、`safety_check` 和 `latest_reminder` 的支持不一致。网关拒绝未知字段时，由使用者关闭对应字段后重试。
- 本地模型的上下文长度、显存和并发能力由使用者本机配置决定。

### 5.2 会话、分组与本地数据

- 会话支持新建、重命名、置顶、分组、归档、批量移动、复制、导出和删除。
- 会话列表按时间分组；存在角色会话时，时间组内再拆分普通聊天与角色子组。
- 时间标签在列表内吸顶，滚动时始终停在可见区顶部；长按时间标签可整组删除，删除前必须二次确认，组内含角色会话时可只删角色会话，也可先把整组归档。
- 多选支持全选、取消全选，以及先点首条再点末条的范围选择；桌面端按住 `Shift` 点击也能直接选中连续区间。
- `30天` 组只显示天数，不再附加“近一个月”后缀。
- 用量明细只保留输入、输出、缓存命中、未命中和命中率，不再显示“模式切换 · 首轮缓存重建”标签。
- 新建对话时先结算上一会话：逐条统计消息数、字符数、分词 Token、接口返回用量与单条占用最高的消息，分片执行并显示进度；完成后弹出只读结算面板，列出消息数、字符数、分词 Token、接口返回用量、上下文占比与占用最高的消息。结算结果只用于展示，不写数据库，不改变会话内容。
- 支持从任意消息创建分支。分支继承分叉点之前的上下文、记忆和场景，不继承分叉点之后的内容。
- 支持重新生成并保留旧回答版本、编辑用户消息、编辑模型回复、删除单条消息和删除会话。
- 本地持久化覆盖会话、分支、消息版本、草稿、附件引用、基础档案、角色卡、世界书、场景、记忆、设置与备份元数据。
- 自动备份写入 `Download/DeepSaga/自动备份`，先写临时文件，核对大小并校验 ZIP 后才发布；默认保留最近 5 份完整备份。
- 自动备份按本机数据版本去重：完整备份成功后，没有新增对话、消息、角色卡、世界书、记忆或设置时不重复写盘；检测到新数据后才恢复按间隔备份。手动“立即备份”不受此限制。
- 导入会话的历史附件若只有本地引用、没有服务端 file id（`serverId` 为空），只保留展示，不进入请求；有 `serverId` 的附件按文件块发送。残缺附件不阻断纯文本对话。
- 导入历史归档前校验 ZIP 结构、条目 CRC、会话 JSON、消息分支和完整性摘要。新导出的每个会话都带消息数量与内容摘要；JSON 仍可解析但消息被截断或正文被改写时，会按“消息数量不一致”或“消息内容与校验值不一致”列出对话标题并排除。没有摘要的旧备份继续按结构与分支校验导入。单个会话 JSON、分支、附件或 ZIP 条目损坏时同样逐对话排除；只有 manifest 缺失、版本不兼容、中央目录不可读或没有任何可用对话时才整体失败。
- 导出历史归档时显示分阶段进度：整理会话（已处理数量）、压缩打包（字节进度）与保存文件，长列表和大量图片下也能看到当前阶段。
- 启动遮罩等会话首屏真正绘制完成后再淡出；淡出期间内容已就位，不再出现空白页一闪。用户气泡与 AI 正文共用上弹入场，系统开启“减少动态效果”时自动关闭。
- 分支、重新生成和导入都会改变后续请求上下文；操作前应确认影响范围。

### 5.3 角色系统

- 全局同一时间只启用一张角色卡。会话可绑定独立角色，绑定优先于全局开关。
- 人物层固定为「一张角色卡 → 一份基础档案 → 一条轻量身份行」三选一，不叠加冲突身份。
- 基础档案包含 32 项，按基本档案、身体与生活、性格与边界、剧情与表达四组排列。
- 角色卡覆盖固定参数、生活细节、性格边界、题材玩法、关系、经历、情景、目标、说话方式、口癖、秘密、补充设定、开场参考、对白示例和卡内系统指令。
- 角色卡或基础档案进入角色上下文时，默认助手提示整体替换为沉浸角色基底：模型直接作为人物本人，用这个人物的感官、记忆、关系和情绪接住当前一拍，不保留“助手正在扮演角色”的中间态。
- 角色正文固定以第一人称「我」叙述自己的动作、感官和心理。第三人称代词只用于他人转述，禁止把角色写成第三人称旁白。
- 支持角色卡搜索、分组、单卡收起、编辑器分组折叠和完成度提示。
- 支持导入 Character Card V2/V3、TavernAI 与 PNG chara。
- 来源与署名分组对全部角色卡开放，不再只给内置卡写死链接。原创角色可以留空；二创、游戏、动漫、小说或他人原创设定请自行填写作者主页，找不到主页时填作品页或其他公开来源文档。留空不会阻止保存，但来源缺失或填错由填写者自行承担。链接只接受 `http` / `https`，仅用于卡片展示，不进入 `system`。
- 用户清空内置卡的来源链接后保持为空，不再被种子数据强行补回；需要纠正错误链接时直接改这张卡，不用改源码。
- 角色卡页固定显示「来源与导入声明」：二创、游戏、动漫、小说和他人原创设定的版权归原作者，导入前需确认使用与分享权限；商用、公开发布或再分发需另行取得授权。
- 内置「大肥鱼」「鲸鱼娘」头像，以及欢迎页、API Key 设置页的大肥鱼插图，使用社区二创原图，不使用上游蓝色鲸鱼。角色原型为「溟月」（上善无形，<https://space.bilibili.com/4456176>），女仆装与 DeepSeek 元素二创由 ZipZipPipe 完成（<https://space.bilibili.com/4168597>），大肥鱼头像由 SlimeNull 绘制（<https://space.bilibili.com/441842015>）；内置卡作者入口指向原型作者上善无形的 B 站主页。具体图片作者、文件与许可见 [assets/fanart/SOURCES.md](assets/fanart/SOURCES.md)。
- 二创图片按 CC BY-NC-SA 4.0 使用：必须署名、禁止商业使用、修改后的图片须以相同协议共享。应用代码的 GPL-3.0 不覆盖这些图片。
- 世界书最多 100 条，支持关键词或正则命中、常驻条目、按角色绑定、单轮预算、最近发言或整段历史扫描、避触词和三级可信度。
- 场景覆盖时间、地点、天气、穿着、心情、关系阶段、氛围与感官、在场人物、目标、冲突悬念和关键物件；支持手填与按轮自动提取。
- 表达提示词支持 `{{user}}` 和 `{{char}}` 占位符。
- 默认不启用角色扮演。清空表达提示词时回到普通 AI 助手，并停用角色卡、基础档案、身份行、场景、世界书与角色记忆。
- 「基础扮演模式」开启后，表达提示词为空或保持默认、且当前没有角色卡或基础档案时，用内置青梅竹马预设「沈知夏」（或下方自定义预设）进入角色扮演；关闭后空/默认提示词回到普通 AI 助手，已有角色卡、手写提示词或基础档案不受影响。内置预设只补人物底色，角色卡、档案、世界书、场景与记忆里的既有描述优先级更高，冲突时以它们为准。设置页提供自定义基础扮演提示词开关与文本框；自定义文本非空时整段替换内置预设，关闭后立即回内置但保留文本。
- 「出戏压制」只在角色对话末尾追加演出规则，压制“按设定”“分析用户意图”这类跳出戏剧的元叙述；普通助手对话不追加。
- 自定义提示词不受基础扮演接管，仅在末尾追加来源说明。

### 5.4 长期记忆

- 记忆分为角色记忆与普通记忆两个独立池，各自有卡片上限、字数上限和注入开关。
- 角色记忆分完整回合、重要场景、关键事实三层。完整回合保留双方原话；重要场景摘出地点、人物、事件、气氛和关键细节；关键事实保存姓名、称呼、关系、喜好、承诺和边界。
- 角色池自动整轮按“玩家名字（玩家本人）”和“角色名字（角色本人）”拆成两张卡，正文不再统一写“用户”；没填名字或名字仍是占位值时回退为“玩家 / 角色”及归属标签。旧卡没有记录名字时，面板按当前玩家名与角色名补显。
- 普通记忆分对话、代码、用户原话、AI 原话四类，按关键词检索。
- 显示名为 AI / DeepSeek 时写入普通记忆；显示名为角色卡名或手写档案名时写入角色记忆，并暂停普通记忆写入与注入。
- 记忆按会话和分支隔离。新建会话不会继承旧会话记忆；分叉会继承分叉点之前的卡片。
- 角色记忆支持关闭、整轮记录、自动提炼三种模式。自动提炼额外发起一次合并请求，并逐条标注 `[玩家本人]` / `[角色本人]` / `[共同经历]`。
- 自动提炼只能替换普通自动回合卡。手动卡、置顶卡、重要场景和关键事实不参与替换，也不参与自动归档。
- 注入顺序为手动记录 → 置顶 → 重要场景 → 关键事实 → 最近回合 → 相关旧卡。
- 手动卡无论是否勾选「主动提起」或「每轮优先」都会排在最前注入；这两个开关只控制角色是否会主动开口，以及是否优先占用置顶预算。
- 记忆面板固定标题、分类与底部补卡区，中间列表独立滚动；顶部配额摘要默认收起，展开可看注入与容量诊断；补卡时暂时收起列表，把完整表单露出来。
- 支持时间锚点召回、记忆面板分类筛选、手动补卡、置顶、编辑、删除、双击跳转、整段保存和分类导入导出。
- 记忆是模型上下文，不是数据库事实。模型可能忽略、误用、重复或混淆记忆内容。

### 5.5 连续语音通话

- 支持 VAD 断句、ASR 转写、流式 TTS、播放中插话打断。
- 通话页使用不透明整屏遮罩，打开即完全覆盖聊天页；通话期间锁定后台滚动，系统权限提示、输入法或页面动画暂停时也不会透出底层内容。
- 点击通话按钮立即进入通话页，麦克风授权在页内等待；拒绝或失败时关闭通话页并提示，不会把聊天页晾在授权提示后面。
- 无活动会话时可直接开麦；首条转写会创建会话并生成标题。
- WebView 采集被系统拦截时，尝试切换原生 `AudioRecord`；原生通道中断后最多重建两次。
- 提供系统录音通道自检，用于区分权限问题与采集问题。
- 语音链路依赖 WebView、麦克风权限、音频焦点和 Android 版本。系统权限拒绝、后台限制或录音通道占用会导致失败。
- 连续语音通话产生文本模型与 TTS 费用。计费由服务商决定。

### 5.6 个性化、Token 与诊断

- 支持用户头像、用户名、角色头像、角色名、头像大小、头像形状、独白置灰、主题色、气泡样式、布局、字体大小和消息间距。
- 个性化设置只影响本机显示，不进入请求，不随设定存档导出。
- 设置页的开关、单选、音色入口、记忆模式卡和角色卡启停按钮必须同时具备可见边框或轨道、选中/关闭状态文字与底色；360px 宽、浅色/深色、旧 WebView 不支持 `color-mix()` 时，由纯色兼容层保留同等轮廓，不靠混色单独表达状态。
- 主页支持自定义 LOGO、头像与标题；台词改为可编辑台词池：单条上限 200 字、总量上限 30 条，自动去空去重。设置页逐条编辑，保存后点击主页头像随机切换台词，池内多于一条时优先避开当前句；全部清空后保存恢复内置 13 条台词。
- 台词池只保存在本机 `replica:home-greeting`，不进入请求，不随设定存档导出。
- 朗读音色入口显示当前音色并可展开试听；试听用当前音色合成一句示例，计入一次 TTS 请求，可随时停止，关闭弹层或切换音色时自动中止。
- Token 统计读取上游返回的 `usage` 字段，记录输入、输出、缓存命中与未命中。
- 应用不计算单价，不汇总账单；余额胶囊按用户配置的聊天端点推导服务端根地址，请求 `/user/balance`，成功时显示可用余额，接口返回 404 或不可用时显示不可用，不推算金额。
- 页面集中列出九类会增加消耗的开关：深度思考、智能搜索、世界书注入、长期记忆、场景自动更新、记忆自动提炼、自动压缩、自动标题、上下文提醒。
- 100 万以下显示完整数字并带千分位；达到 100 万才缩写为 `1M` / `1.1M`。
- 缓存命中由上游按从第 0 个 token 开始的完整前缀判断，中间相同不算命中。切换模型、角色卡、分支、开关状态，编辑历史，触发压缩或 `latest_reminder` 变化，均会导致前缀改变；诊断会用逐条消息链指纹定位最早断点。
- 每次带 `usage` 的请求都会留一条本地缓存样本（最多 80 条）：记录 `system` 指纹与字数、动态标记、未替换占位符、`turnContext` 与 `latest_reminder` 长度、消息数、历史轮数、摘要指纹、配置指纹、逐条消息链指纹和命中率。消息链只保存累计 hash 与角色，不保存正文；为控制存储，只有最近两条样本保留完整逐条链，单条最多 512 条消息，其余样本只留整轮指纹；向量只用于比较，不保存聊天正文或 API Key。
- 缓存 usage 兼容 DeepSeek 的 `prompt_tokens_details.cached_tokens` 与顶层 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`；Anthropic 兼容接口缺缓存字段时仍记录输入/输出，并标记“字段缺失”，不会把整条 usage 丢掉。会话用量面板在全部请求都缺缓存字段时直接显示“字段缺失”，不再把缺字段画成 0.0%。
- 会话用量面板只在异常时显示缓存诊断卡：同一配置下 `system` 指纹变化、连续两轮低命中、从健康值骤降、前缀断点、连续压缩改写首条 user 摘要时，列出可能原因和证据；断点会写成“第几条消息、什么角色开始与上一轮不同”。首轮和配置刚切换不报警；第一次压缩降为提醒；接口完全不返回缓存字段时只提示“无法判断”，不冒充提示词丢失。
- 与 DeepSeek 官方 `deepseek-harness` 的实现对齐点是：稳定前缀优先、逐条前缀摘要、usage 字段保真、区分“字段缺失”和“真实 0 命中”。赤石科技公开的两个仓库分别是不发模型请求的 DSH 插件和基于 WebView2 的客户端外壳，不参与消息拼装与缓存控制，因此只作为“第三方客户端直接继承官方行为”的旁证。
- “运行诊断并保存日志”覆盖提示词静态 / 动态分层、缓存样本与命中趋势、接口配置、角色来源链接、渲染横向溢出、弹层滚动锁、动画数量、事件循环迟到、帧间隔、JS 进程内存、存储配额、网络、消息 ID 重复与半条记录。问题分“问题 / 提醒”两级，日志逐项写证据。
- 关于区恢复“检查更新”：读取仓库 `package.json` 版本并与应用内版本比较；有新版本时再点一次打开下载页；GitHub raw 与 jsDelivr 依次尝试，读取失败只提示网络问题，不影响聊天。
- 诊断日志用于排查白屏、卡顿、请求失败和权限问题。日志可能包含请求元信息、角色名和来源链接，对外提供前必须检查是否含 Key、地址或聊天内容。

### 5.7 安全审核与内容责任

- `safety_check` 默认开启。开启时请求体携带该字段，内容尺度与过滤结果由服务商或网关按其规则决定。
- `safety_check` 是应用层请求字段控制，不是本地内容过滤器；不替代上游服务商或网关的底层审查。
- 关闭 `safety_check` 后不再发送该字段，本应用也不在本地替代服务商审核。模型输出、发送内容以及公开传播、截图分享或上传所产生的平台规则与法律后果，由使用者自行承担。
- 本地对话属于使用者的私密空间。普通亲密、情感表达、关系推进、冲突与道德分歧由角色按自身性格自然接住，不切成客服说教；亲密互动不写露骨性描写。现实违法、侵害他人、制造危险物、伤害动物或严重自伤的具体操作仍拒绝，拒绝由人物以情绪化、直白的方式表达。
- 服务端拒答时，消息标记为 `refusal`。可配置是否保留已下发正文、被拒轮次是否进入上下文，以及拒答话术。
- 本地关键词拒答只检查当前输入文本，命中后直接返回话术，不调用接口。该功能只做字面匹配，不识别语义、谐音或变体，不替代完整内容审核。
- 内部 guard 分工：`ROLEPLAY_SAFETY_GUARD` 保留现实违法、伤害与露骨描写的尺度；`LOCAL_ENVIRONMENT_GUARD` 只压自我审查式旁白、分析式开场和免责说教；`LOCAL_PRIVATE_PROTOCOL` 负责私密空间、真实人格与极端边界；`ROLEPLAY_STRICT_GUARD` 负责身份、视角、思维链与事实连续性。四者职责不同，不因 `safety_check` 开关而删除，也不应作为“冗余自我设限”清理。
- 开启或关闭审核开关不改变使用者对输入内容、模型输出、传播行为和实际后果的责任。
