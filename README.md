# DeepSeek Replica 二创版

> 一个 Android 上的本地优先 AI 聊天客户端。日常聊天、角色卡、世界书、场景、长期记忆和连续语音通话都在同一个应用里跑。  
> 当前源码版本：**0.8.62**。仓库只提供源码，不发布 APK。

## 项目状态

这个仓库不是从零写出来的。基础工程来自 [LiJiaHua1024/deepseek-app-replica](https://github.com/LiJiaHua1024/deepseek-app-replica)，一个尽量复刻 DeepSeek 手机端交互的 Android 客户端；部分角色扮演、模型接口、记忆、语音和历史归档能力移植自赤石科技的 [YanJiuWeiYuanHui/DeepChat](https://github.com/YanJiuWeiYuanHui/DeepChat) 1.1.3；两个项目共同的上游是 [deepseek-ai/chat-demo](https://github.com/deepseek-ai/chat-demo)。在此基础上继续修请求层、补角色运行时、做稳定性和成本观测，才变成现在这个版本。

需要先把话说清楚：

- 这是二次创作，不是上述任何项目的官方分支，也不代表 DeepSeek 官方。

- **功能的完整性和稳定程度无法保证。** 能跑通主要路径，不代表没有边界问题；需要后续接手的人继续测试、观察和修。

## 最短上手路径

1. 按“构建”一节自行编译，或使用你自己信任的构建产物。仓库不附带签名文件。
2. 打开设置，填入 API Key、接口地址和模型名；按服务商要求选择 Chat / Responses / Anthropic / 自定义网关。
3. 需要角色扮演时，新建或导入角色卡，按需绑定世界书、填写场景，再打开角色扮演开关。
4. 日常聊天可以直接用；长对话建议先看一遍“Token 与费用”页，确认哪些开关会增加消耗。
5. 重要会话、角色卡和设定，定期导出备份。卸载应用会清掉本地数据。
6. 出现白屏、闪退、麦克风不可用之类的问题，先看诊断日志，再判断是应用、系统权限还是接口网关的问题。

## 功能清单

下面按使用场景列。每一项都写了它大概解决什么问题、从哪里进、以及需要注意的地方。功能多不代表每一项都经过同等程度的验证。

### 1. 日常聊天

**能做什么**

- 支持 Chat Completions、Responses、Anthropic 和自定义网关等请求形态；本地模型可接 Ollama、LM Studio、vLLM、LocalAI 一类兼容端点。
- 渲染 Markdown、表格、代码块、KaTeX 公式和 Mermaid 图表。
- 支持图片、文件附件，支持联网搜索，支持回复朗读。
- 支持重新生成、创建分支、会话分组、归档、批量操作。
- 支持主题色、气泡样式、消息密度、设置搜索。
- 支持自动备份、历史导入导出、会话包导出。

**怎么用**

在设置里选好接口类型和模型，填 Key 和地址，回首页直接发消息。需要对比不同回答时用“重新生成”；想保留原回答、再走另一条剧情时用“分支”。附件和联网搜索会额外增加请求 token，长对话前先确认接口是否支持对应字段。

**注意**

- 不同网关对字段支持不一致。某些端点会忽略图片、工具调用、搜索或 `reasoning` 参数，这不是前端吞了，是上游没实现。
- 附件、搜索结果和长历史都会进入上下文。功能能用，不等于每一轮都便宜。
- 主题、气泡和字体只影响显示，不影响请求内容。

### 2. 角色扮演

**能做什么**

- 角色卡最多 50 张，支持自定义头像、标签筛选、开场白；内置大肥鱼、鲸鱼娘、猫娘三张卡。
- 支持导入 Character Card V2/V3、TavernAI 和 PNG chara。
- 世界书最多 100 条，支持关键词或正则命中、常驻条目、按角色绑定、单轮预算。
- 场景可以手填，也可以按轮自动提取。
- 角色表达支持内心独白、动作样式、`{{user}}` / `{{char}}` 占位符、玩家括号独白、称呼约定和长消息折叠。
- 最终 system 的组装顺序是：记忆 → 场景 → 世界书 → 角色卡 → 手写提示词。
- 关闭角色扮演时，当前角色卡的人设可以保留；世界书、场景和演出规则暂停，重新打开后恢复完整扮演。

**怎么用**

先建卡或导入卡，再决定要不要绑世界书。世界书条目不是越多越好，常驻条目每轮都会进上下文；按关键词命中的条目更省。场景可以手写一段当前局面，也可以让应用按轮提取。打开角色扮演后，角色卡、世界书、场景和记忆会按固定顺序拼进 system；关闭扮演但保留人设，适合临时写代码、查资料，又不想把角色配置清空。

**注意**

- 角色像不像，最终取决于模型本身、角色卡写法和上下文长度。应用只负责把设定按顺序送进去，不能保证每个模型都演得好。
- 导入的角色卡如果带前端不支持的字段，会被忽略或降级处理；导入后最好自己看一遍开场白、示例对话和系统提示。
- 世界书常驻条目、自动场景提取、记忆自动提炼都会增加请求量。角色卡越细、世界书越长，成本越高。
- 长消息折叠只是显示层处理，不会减少送进模型的内容。

### 3. 长期记忆

**能做什么**

- 记忆按会话分支隔离，默认不会跨分支串线。
- 支持关闭、整轮记录、自动提炼三种模式。
- 记忆卡片可编辑、删除、手动补充。
- 上限最高 9999 张，字符预算默认 1M。
- 记忆可以单独导出导入；角色卡、头像、世界书、场景可以打成设定存档；整个会话也能单独导出。

**怎么用**

不想让应用自动总结，就关掉记忆或只用整轮记录；想让模型自己提炼，就开自动提炼。记忆卡片可以手动修，模型写偏了直接改，不要指望它每次都总结得准。换设备或重装前，先把记忆和设定存档导出。

**注意**

- 自动提炼本身要发请求，也会消耗 token；记忆越多，后续请求的上下文越大。
- 记忆是“给模型的参考”，不是数据库事实。模型仍可能忽略、误用或重复记忆里的内容。
- 分支隔离是设计行为。需要共享设定的，用角色卡和世界书，不要指望记忆跨分支自动同步。

### 4. 连续语音通话

**能做什么**

- VAD 断句、ASR 转写、流式回复分句 TTS、播放中插话打断。
- 没有活动会话也能直接开麦；首条转写会新建会话并生成标题。
- 网页采集被系统拦下时，会尝试切换到原生 `AudioRecord`。
- 原生通道读取中断会自动重建，最多两次。

**怎么用**

在首页点电话按钮，第一次开口后会自动建会话。说话时不用等整段结束，VAD 会断句；模型回复会分句转成语音，播放中可以插话打断。麦克风权限、媒体音频焦点和系统录音通道由 Android 和厂商 ROM 控制，应用只能尽量兜底。

**注意**

- 语音链路依赖 WebView、麦克风权限、音频焦点和系统版本。不同机型表现可能不一样，无法保证每台设备都稳定。
- 原生直录是兜底，不是万能方案；系统权限被拒绝、后台被限制或录音通道被占用时，仍然可能失败。
- 通话同样走文本模型和 TTS 接口，会产生 token 或语音服务费用。长通话前先确认计价方式。

### 5. 数据、备份与迁移

**能做什么**

- API Key 在 Android 侧用 Keystore 加密存储。
- 会话、角色卡、世界书、场景、记忆和附件保存在设备本地。
- 支持自动备份、历史归档导入导出、会话包、设定存档、记忆单独导出。
- 导出的备份不包含 API Key。

**怎么用**

在设置里开自动备份，重要会话手动再导一份。换设备时先导出会话包和设定存档，再在新设备导入。历史归档支持合并或替换，导入前先看清提示。

**注意**

- 没有账号体系，也没有中转服务器。数据只在本机，卸载应用会清掉本地数据。
- 备份文件可能包含角色卡、聊天记录和图片。发给别人之前自己检查内容。
- 导出格式有版本差异，跨版本导入不一定百分之百兼容；重要数据保留原始备份。

### 6. Token、费用与诊断

**能做什么**

- 显示每次请求的实际用量、会话统计、缓存命中和未命中。
- 集中列出九个真实会增加消耗的开关：深度思考、智能搜索、世界书注入、长期记忆、场景自动更新、记忆自动提炼、自动压缩、自动标题、上下文提醒。
- 显示峰谷时段提示。
- 记录诊断日志，帮助判断白屏、卡顿、请求失败和权限问题。
- 启动公告说明本次版本的变化和已知边界。

**怎么用**

长会话前后各看一次“Token 与费用”页。先看请求次数，再看总输入、缓存命中、未命中，最后看命中率。页面里的开关说明不是装饰，关掉一个就少一份上下文或一次额外请求。诊断日志适合排查“是应用卡了，还是接口没返回”。

**注意**

- 这些统计是本地记录，不是官方账单。具体口径见下一节。
- 九个开关只是提醒，不会替用户自动关掉功能；省不省、怎么省，由使用者自己决定。
- 诊断日志可能包含请求元信息，发给别人前先检查有没有 Key、地址或聊天内容。

### 7. 界面与长期使用

**能做什么**

- 设置搜索、主题色、气泡样式、消息密度、窄屏角色卡单列。
- 会话分组、归档、批量操作。
- 长会话动画和低端 GPU 的降级处理。
- 白屏、闪退、TDZ、`inert` 卡死、诊断误报等问题的修复。

**怎么用**

窄屏设备上角色卡会自动单列，不需要手动改布局。设置项多的时候直接用搜索，不用一层层翻。低端机如果出现黑帧或卡顿，先关掉复杂主题和长动画，再看诊断日志。

**注意**

- 界面适配没有覆盖所有分辨率、字体缩放和厂商 ROM。
- 主题和气泡只影响显示；长会话的卡顿更多来自消息数量、图片和 WebView 渲染，不是换一个主题就能解决。

## Token 计费与用量明细：先看清它是什么

这一节是给第一次用 API 的人看的。很多人第一次看到“几十万 token、几块钱”会以为数据是假的，或者以为应用在乱扣费。先把口径讲清楚。

### 数据从哪里来

应用本身不计算价格，也不读取你的账户余额、积分或额度。页面里的 token 数字来自每次请求返回的 `usage` 字段，例如输入 token、输出 token、缓存命中 token、缓存未命中 token；应用把这些返回值记录在本地，再按会话汇总。

这意味着：

- 上游返回什么，页面就显示什么；上游不返回缓存字段时，页面不会编造一个命中率。
- 不同网关、不同模型、不同版本的字段名可能不一样；有的只返回总 token，有的不返回缓存明细。
- 本地汇总可能有四舍五入、请求失败重试、流式中断等误差，不能拿它当财务凭证。
- **余额、单价、扣费和发票，以服务商后台为准。** 本应用不管理余额，也不代表 DeepSeek 官方 API 或任何网关的计费立场。

### 页面字段怎么读

- **总消耗 / 总输入 / 总输出**：这个会话累计送进模型和模型返回的 token，不等于账单金额。
- **请求次数**：真正发出去的请求数。一次请求也可能带几十万 token 的上下文。
- **缓存命中**：上游复用了之前相同前缀的 token，通常按更低的缓存价格计费。
- **缓存未命中**：这次新上传、没有被复用的 token，通常按正常输入价格计费。
- **缓存命中率**：一般按“命中 /（命中 + 未命中）”估算。输出 token 通常单列，不计入这个分母；具体以页面显示为准。

### 三个最容易误解的地方

**第一，分支不是从零开始的新会话。**

分支是在同一条历史主干上分叉，角色卡、世界书、场景、记忆和分叉点之前的全部对话仍然在上下文里。分支只改变分叉点之后的走向，不会把前面的历史清空。如果分支真的从零开始，它就不是剧情分支，只是一个新会话。

**第二，总 token 大，不等于账单一定高。**

如果大部分上下文命中缓存，计费的只是未命中和新增部分，账单可能很温和。反过来，总 token 不算特别大，但缓存命中率很低，几乎全部按输入 token 计费，账单反而会明显上升。看总量之前，先看命中率。

**第三，命中率低不是“假数据”。**

命中率低通常说明这次请求没有复用上之前的上下文：会话太长、前缀变了、世界书或角色卡改动较大、网关没有透传缓存字段，或者模型本身不支持缓存。页面显示的是上游返回值，不是本地猜的。要判断钱花在哪，看请求次数、未命中 token 和当时开了哪些功能，比只看总金额有用。

### 成本观察建议

下面这些是使用经验，不是官方定价标准。不同模型、不同网关、不同账户的单价差别很大，只能当参考。

- **命中率长期在 70% 以上**：通常属于健康区间，增量计费为主，可以继续聊。
- **命中率落到 30%～50%**：还能用，但每次请求的开销会上升，长会话要开始留意余额。
- **命中率低于 20%，甚至只有百分之几**：这是明确的高成本信号。哪怕只发一句很短的话，也会带着很长的历史一起提交。
- **余额快速跳水**：如果余额本来有十几块，发了一到五句短消息后突然只剩一两块，基本可以判断这个会话的缓存已经失效。旧会话可以留着，等有预算再玩；想省钱就复制角色配置、新建会话，把上下文重置。

分支、续写、重新生成都会继承当前上下文，也会计入统计。它们适合推进同一故事的另一种可能，不适合用来“零成本重开”。要隔离上下文、控制成本，正确做法是新建会话，不是在同一条超长主干上不断分支。

这套统计的用途是提醒使用者定时查看、观察和分析，不是替代服务商账单，也不构成任何官方计费解释。遇到金额争议，以服务商后台记录为准。

## 二创具体改了什么

不是简单换皮。主要动了四块：

1. **请求层**：修掉自定义接口下 `system` 为空的问题；把角色卡、世界书、场景、记忆、手写提示词按固定顺序拼进 system；补齐 Chat / Responses / Anthropic / 自定义网关的请求差异、采样参数、拒答处理和标题策略。
2. **角色层**：重做角色卡、世界书、场景、标签、开场白、头像、内置卡、导入格式和角色表达样式。原来的“提示词输入框”变成了一套可切换、可保存、可导出的角色配置。
3. **记忆与数据层**：长期记忆从单轮文本变成按分支隔离的卡片系统；补上记忆归档、会话包、设定存档、自动备份和 Token 账本。
4. **稳定性与产品化**：处理白屏、闪退、TDZ、`inert` 卡死、低端 GPU 黑帧、长会话动画泄漏、诊断日志误报，以及设置搜索、主题、峰谷提示、成本页这些长期使用才会需要的东西。

## 只开源，不发 APK

开源代码和分发安装包是两件不同的事。前者交出的是可检查的实现；后者交出的是“我替你签过名、我保证它能装、出了问题找我”的信任。这个仓库只能承担前者。

### 1. 签名和更新链没法一起交出去

二创使用的是个人调试签名，不是可以长期持有的发布证书。继续发 APK，等于让所有人信任一把在个人手里的钥匙；项目停止维护后，这把钥匙也不该继续代表这个软件。没有稳定的发布仓库、签名校验和回滚方案，“最新版”只是一个随时可能失效的下载链接。

### 2. 二进制不能自证

源码能看、能 diff、能自己编译，APK 不能。一个被重新签过名的包，图标、版本号、关于页都可以做得一模一样，里面多一个权限、一个上报地址，普通用户看不出来。只发源码，至少每个人都能从同一份代码开始验证。

### 3. API Key 和聊天记录不是演示数据

这个应用要填自己的 API Key，会话、角色卡、记忆和附件都落在本机。一个来路不明的改包，最坏的情况不是闪退，是密钥和聊天内容被带走。源码公开、用户自己构建，至少能把“谁编的、从哪来的”查清楚。

### 4. 上游代码和素材的授权边界

基础工程是 GPL-3.0，DeepChat 和 chat-demo 是 MIT，内置角色卡、头像和部分社区设定还牵涉角色形象与二创素材。源码仓库可以保留 LICENSE、NOTICE、MIT 全文和逐项署名；做成 APK 往外发，就会把代码许可、角色素材、商标和平台规则混成一笔账。

### 5. 平台规则和分发责任

应用商店、企业分发、侧载渠道各有自己的审核、隐私披露、年龄分级和合规要求。这个仓库没有开发者账号，也没有为上架做过合规审查。把 APK 挂出去，等于默认替它承担这些责任。

### 6. 没有长期维护能力

二次开源之后，不负责往后的更新，也不分发 APK。软件还在观察期，系统版本、WebView、麦克风权限、厂商 ROM 都会变。继续挂安装包，只会制造“有人在持续维护”的错觉；用户装上一个不再更新的包，出了问题连该找谁都不知道。

### 7. 防止被拿去冒充

仓库不提供“官方包”。别人拿一个 APK 来冒充这个项目时，至少还能要求他给出提交记录和构建方式。一旦有了官方下载链接，伪造包就有了天然的话术。

### 实际怎么用

- **想自己用**：按下面的构建步骤编译，自己生成签名，自己承担系统兼容、API 费用和数据备份。源码许可证允许你自己构建和使用。
- **拿到别人转发的 APK**：先问清楚对应的提交、构建命令和签名来源。答不上来就不要装，更不要在里面填 API Key。它不是这个仓库发布的，无法保证没有被改过。
- **想再分发**：GPL-3.0 允许符合许可证的再分发，但那是“你编译的版本”，不是这个仓库的官方包。请保留 LICENSE、NOTICE、上游署名，自己处理角色素材、商标和平台合规。

这个仓库的交付物只有源码。你可以自己编译、自己签名、自己装；编译出来给谁、怎么用、出了问题怎么办，都由你自己承担。个人自用或小范围测试没有问题，把没有来源的成品当成这个项目的官方版本流通，不行。

## 构建

前端：

```bash
pnpm install
pnpm type
pnpm build
```

构建产物在 `dist/`。

Android 工程保留在 `android/`，当前配置使用 Gradle 9.7.1、AGP 9.4.0、compileSdk 37、minSdk 29。环境版本对不上时，按自己的 SDK 调整 `android/app/build.gradle`：

```bash
cd android
./gradlew assembleDebug
```

仓库不附带 `release.jks`、`debug.keystore` 或任何签名文件。需要发布包时，自己生成并保管签名；不要把密钥提交进来。

应用内的更新检查入口保留为空仓库地址，默认不会去 GitHub 拉 APK。想接自己的发布源，再填 `UpdateRelease.java` 里的 `REPOSITORY`；本仓库不提供可下载的成品。

## 数据与隐私

- 没有账号体系，也没有中转服务器。API Key 由你自己填，Android 侧走 Keystore 加密存储。
- 会话、角色卡、世界书、场景、记忆和附件都保存在设备本地。卸载应用会清掉本地数据，重要内容先导出。
- 请求只会发往你配置的接口地址。你用了哪个网关、那个网关怎么记录请求，不在这个仓库的控制范围内。
- 导出的备份不包含 API Key；角色卡和设定存档是否含图片，以导出时的提示为准。

## 使用边界

这个项目是工具，不是官方客户端，也不是内容平台。不要拿它做违法、侵权、骚扰、冒充官方或绕过平台规则的事。AI 生成的内容、API 费用、账号状态和对话后果，都由使用者自己承担。

这不是一个有 SLA 的商业项目。Issue 可能回，也可能不回；兼容性问题、系统差异、厂商 ROM 的限制，需要自己排查。仓库能做的，是把代码和边界写清楚，不能替每个人保证“在你这台机器上一定没问题”。
