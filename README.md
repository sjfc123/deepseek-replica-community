# DeepSeek Replica 二创版

> 一个 Android 上的本地优先 AI 聊天客户端。日常聊天、角色卡、世界书、场景、长期记忆、连续语音通话和费用观测都在同一个应用里跑。  
> 当前源码版本：**0.8.67**。  
> GitHub 仓库：[sjfc123/deepseek-replica-community](https://github.com/sjfc123/deepseek-replica-community)

## 项目状态

这个仓库不是从零写出来的。基础工程来自 [LiJiaHua1024/deepseek-app-replica](https://github.com/LiJiaHua1024/deepseek-app-replica)，一个尽量复刻 DeepSeek 手机端交互的 Android 客户端；部分角色扮演、模型接口、记忆、语音、历史归档和消息操作参考或移植自赤石科技的 [YanJiuWeiYuanHui/DeepChat](https://github.com/YanJiuWeiYuanHui/DeepChat) 1.1.3；两个项目共同的上游是 [deepseek-ai/chat-demo](https://github.com/deepseek-ai/chat-demo)。在此基础上继续修请求层、补角色运行时、做稳定性和成本观测，才变成现在这个版本。

需要先把话说清楚：

- 这是二次创作，不是上述任何项目的官方分支，也不代表 DeepSeek 官方。

- **功能的完整性和稳定程度无法保证。** 能跑通主要路径，不代表没有边界问题；需要后续接手的人继续测试、观察和修。
- **不保证没有 bug。** 这个仓库不是商业产品，没有 SLA，也没有完整的回归测试矩阵。
- 仓库保存的是源码。构建、签名、打包和分发由实际操作的人负责，相关代价也由操作者承担。

## 最短上手路径

1. 按“构建”一节自行编译，或使用你自己信任的构建产物。仓库不附带签名文件。
2. 打开设置，填入 API Key、接口地址和模型名；按服务商要求选择 Chat / Responses / Anthropic / 自定义网关。
3. 先发一条普通消息，确认接口能返回；再开角色扮演、附件、搜索和语音。
4. 需要角色扮演时，新建或导入角色卡，按需绑定世界书、填写场景，再打开角色扮演开关。
5. 长对话前先看一遍“Token 与费用”页，确认哪些开关会增加消耗。
6. 重要会话、角色卡和设定，定期导出备份。卸载应用会清掉本地数据。
7. 出现白屏、闪退、麦克风不可用之类的问题，先看诊断日志，再判断是应用、系统权限还是接口网关的问题。

## 功能清单

下面按使用场景展开。每一项都写了用途、入口、边界。功能多，不代表每一项都经过同等程度的验证。

### 1. 模型与接口

**能做什么**

- 支持 Chat Completions、Responses、Anthropic 和自定义网关等请求形态。
- 本地模型可接 Ollama、LM Studio、vLLM、LocalAI 一类兼容端点。
- 支持自定义请求头，格式为多行 `Key: Value` 或 JSON 对象；同名请求头会覆盖内置值，包括 `Authorization`。
- 支持回复菜单里的“生成配图”，可设置绘图模型名和图片尺寸，默认模型 `gpt-image-1`、默认尺寸 `1024x1024`。
- 自定义接口下不再把 `system` 整个置空，角色设定、世界书、场景和记忆能按顺序进入请求。

**怎么用**

在设置里选接口类型，填地址、Key 和模型名。第三方网关要求额外鉴权时，在自定义请求头里写 `Authorization: Bearer <key>`；网关不认识 DeepSeek 扩展字段并返回 400 时，关闭 `safety_check` 和 `latest_reminder` 再试。先用一条普通消息确认接口能返回文本，再开角色扮演和附件。

**注意**

- 不同网关对字段支持不一致。某些端点会忽略图片、工具调用、搜索或 `reasoning` 参数，这不是前端吞了，是上游没实现。
- 自定义头会覆盖同名默认头。写错 `Authorization` 会让请求直接失败，格式错误的行会被忽略。
- 本地模型的上下文长度、显存和并发能力由你自己的机器决定。
- 生成配图走单独的图片接口，是否支持、怎么计费由服务商决定；不是所有网关都能用。

### 2. 生成参数与请求

**能做什么**

- 通用采样：温度 `temperature`、Top P、最大输出 tokens；留空表示不发送，沿用服务端默认值。
- 角色扮演采样：单独一套温度、Top P、最大输出；启用角色卡时优先使用，未填写的项继承通用值。
- 推理强度：`thinkingEffort` 可选 low / high / max，仅在 OpenAI 协议且开启深度思考时下发 `reasoning_effort`。
- 上下文提醒 `latest_reminder`：每轮附带当前日期、星期、大致位置和语言快照；隐私敏感或需要完全虚构时间线时可关闭。
- 服务端自动生成标题：首轮请求携带 `title` 字段；关闭后由首条消息文本生成标题。
- 安全审核 `safety_check`：开启时请求体携带该字段，由服务端按其规则检查；关闭后不再发送该字段。
- 本地 Token 限额：达到设定值提示一次，并在顶栏显示胶囊；只读接口返回的 `usage`，不改变服务端计费上限。

**怎么用**

日常问答温度可以低一些，角色扮演常用温度 0.8–1.1、Top P 0.9–1。回复偏离主题就降温度；句式重复就小幅上调或降 Top P；回复被截断就提高最大输出。角色卡启用时，角色扮演参数优先；不需要单独调 Top P 和最大输出时留空即可。

**注意**

- 参数范围由模型决定。温度一般 0–2、Top P 0–1、最大输出 1–1,000,000，但超出接口范围会被拒绝。
- 留空和填 0 不是一回事：留空是不发送，填 0 是明确发送 0。
- `latest_reminder` 会带大致位置，不需要就关掉。
- `safety_check` 是请求字段，不是本地过滤器；关掉只代表本应用不再附加这一层，服务商仍可能审核。
- 自定义网关不认识扩展字段时，先关 `safety_check` 和 `latest_reminder`，不要一上来就改代码。

### 3. 日常聊天

**能做什么**

- 渲染 Markdown、表格、代码块、KaTeX 公式和 Mermaid 图表。
- 支持图片、文件附件，支持联网搜索，支持回复朗读。
- 支持重新生成、创建分支、编辑用户消息、编辑模型回复、复制、删除单条消息、长按菜单。
- 支持会话分组、归档、批量操作、删除会话。
- 支持主题色、气泡样式、消息密度、设置搜索、字体大小。
- 支持自动备份、历史导入导出、会话包导出。
- 支持自动压缩、自动标题、上下文提醒和 Token 限额提醒。

**怎么用**

在设置里选好接口类型和模型，填 Key 和地址，回首页直接发消息。需要对比不同回答时用“重新生成”；想保留原回答、再走另一条剧情时用“分支”；需要修正自己或模型的话时用“编辑”；不需要的会话可以归档或删除。附件和联网搜索会额外增加请求 token，长对话前先确认接口是否支持对应字段。

**注意**

- 分支不是新会话，它会继承分叉点之前的全部上下文。分支越多，后续请求的历史越长。
- 编辑模型回复会改写该条消息并影响后续上下文；删除消息也会改变历史，操作前想清楚。
- 附件、搜索结果和长历史都会进入上下文。功能能用，不等于每一轮都便宜。
- 主题、气泡和字体只影响显示，不影响请求内容。
- 自动压缩和自动标题本身也可能发请求，具体看当前实现和开关状态。

### 4. 角色扮演

**能做什么**

- 角色卡最多 50 张，支持自定义头像、标签筛选、开场白；内置大肥鱼、鲸鱼娘、猫娘三张卡。
- 支持导入 Character Card V2/V3、TavernAI 和 PNG chara。
- 世界书最多 100 条，支持关键词或正则命中、常驻条目、按角色绑定、单轮预算；默认单轮 1,000 字、最多 6 条，可按 500–20,000 字调整。
- 支持导入 SillyTavern 世界书和 `character_book` 一类条目。
- 场景可以手填，也可以按轮自动提取。
- 角色表达支持内心独白、动作样式、`{{user}}` / `{{char}}` 占位符、玩家括号独白、称呼约定和长消息折叠。
- 支持“压制「按设定」这类元叙述”：在 system 末尾追加强制约束，不提及规则、不复述设定、不分析用户意图、不使用 AI 视角评述。
- 最终 system 的组装顺序是：记忆 → 场景 → 世界书 → 角色卡 → 手写提示词。
- 关闭角色扮演时，当前角色卡的人设可以保留；世界书、场景和演出规则暂停，重新打开后恢复完整扮演。

**怎么用**

先建卡或导入卡，再决定要不要绑世界书。角色卡负责“是谁、和 {{user}} 什么关系、怎么说话”；世界书写“地点、组织、过去发生过什么”；场景写“现在几点、在哪、谁在场”。世界书条目不是越多越好，常驻条目每轮都会进上下文；按关键词命中的条目更省。场景可以手写一段当前局面，也可以让应用按轮提取。

**三个上手示例**

1. **夜班便利店**
   - 角色卡：你是{{char}}，28 岁，夜班便利店店员。对{{user}}克制但关心，称呼“你”。用对话和动作推进，不复述设定，不替{{user}}决定行动。
   - 世界书：标题「便利店仓库」，关键词「仓库、后门」，正文「后门锁坏，只有店长知道」。
   - 场景：凌晨两点，便利店仓库门口，{{user}}刚下夜班。

2. **雨夜旧港侦探**
   - 角色卡：你是{{char}}，落魄侦探，说话短、观察细，不主动解释自己的过去。
   - 世界书：标题「旧港区」，关键词「码头、雨夜、失踪」，正文「三年前这里沉过一艘没有登记的货船」。
   - 场景：暴雨，旧港区码头，{{user}}带着一张被雨水泡皱的照片。

3. **日常陪伴**
   - 角色卡：你是{{char}}，住在{{user}}隔壁的猫娘室友，语气轻，偶尔撒娇，但有自己的生活节奏。
   - 世界书：标题「冰箱贴」，关键词「晚饭、冰箱、超市」，正文「冰箱上贴着上周的超市小票，背面写了购物清单」。
   - 场景：周末午后，厨房，{{user}}刚打开冰箱。

**注意**

- 角色像不像，最终取决于模型本身、角色卡写法和上下文长度。应用只负责把设定按顺序送进去，不能保证每个模型都演得好。
- 导入的角色卡如果带前端不支持的字段，会被忽略或降级处理；导入后最好自己看一遍开场白、示例对话和系统提示。
- 世界书常驻条目、自动场景提取、记忆自动提炼都会增加请求量。角色卡越细、世界书越长，成本越高。
- 长消息折叠只是显示层处理，不会减少送进模型的内容。
- 角色扮演关闭后保留的是人设，不是完整扮演状态；世界书和场景不会继续注入。
- 示例里的设定只是写法参考，不要直接把别人的角色卡、世界书或付费设定拿来公开分发。

### 5. 长期记忆

**能做什么**

- 长期记忆分两个顶层分类：**角色记忆**与**普通记忆**。旧版卡片没有分类字段，统一按角色记忆处理；原文、时间线、置顶、归档和注入顺序都不改。
- **角色记忆**继续走完整回合卡、时间锚点召回、好感与共同经历逻辑；**普通记忆**是开发与问答知识库，分成对话、代码、用户说的话、AI 说的话四个子分类，每条消息独立成卡，不强行合成回合。
- 普通记忆按关键词检索，不做时间线、好感或关系阶段召回；手动卡和置顶卡优先，其余按与当前问题的词块重合度取卡。角色扮演开启时不注入普通记忆，避免代码、开发日志污染人设。
- 消息长按保存的二次确认弹窗可以选择“角色记忆”或“普通记忆”。普通记忆下可选自动识别、对话、代码、用户原话、AI 原话；三连反引号代码块自动预选代码分类，单行单个反引号不算代码，最终分类仍可手改。
- 非角色扮演对话里，回复出现三连反引号代码块时自动存一张普通-代码卡；同一条回复只记一次，可在面板关闭或删除。
- 普通记忆与角色记忆各有独立卡片上限、字数上限与注入开关。默认普通记忆 300 张、200,000 字，角色记忆 60 张、1,000,000 字，都可以在设置里改。
- 记忆按会话分支隔离：换一个新会话，旧会话的记忆不会跟过去；从旧消息分叉，会继承分叉点之前的卡片。分支不是从零开始，它继承的是同一条时间线。
- 支持关闭、整轮记录、自动提炼三种角色记忆模式。整轮记录不额外发请求；自动提炼会额外发一次合并请求。
- 整轮记录改成完整回合卡：用户原话和角色回应都保留，不再压成前 120 / 180 字；卡片头部写入时间、轮次和记录时的关系阶段，正文按“用户 / 角色”分段。这样一张卡就是一段可回看的经历，而不是一句摘要。
- 卡片挂在这一轮的消息上，跟着当前会话和分支走。一轮轮累积下来，会形成“我们一起做过什么、说过什么、关系走到哪一步”的记忆链。
- 支持时间锚点召回：玩家提到“今天 / 昨天 / 前天 / 大前天 / 上周 / 上周三 / 这周 / 这周三 / 上个月 / 去年 / 前年 / 前几天 / 前阵子 / X 月 X 日 / 去年 X 月 X 日”这类时间时，命中时间范围的旧卡会进入相关名额，即使没有直接关键词也能被带进这一轮。只写“X 月 X 日”且日期落在未来时，按记忆语境回退到去年。
- 注入按“手动记录 → 置顶 → 最近 → 相关旧卡”排序。手动卡是玩家明确要求角色记住的姓名、偏好、习惯和经历，不参与最近 12 张的竞争，优先进入上下文；置顶卡最多 8 张，最近卡 12 张，和当前发言相关或命中时间锚点的旧卡最多 12 张。其余卡片留在面板和归档里，不参与这一轮。
- 手动卡优先回答已知信息：玩家问“我最喜欢吃什么 / 用户喜欢什么 / 韩寒喜欢什么 / 角色喜欢什么”这类问题时，记忆块要求模型先查手动记录和已有卡片，有明确记录就按记录回答，不要说不确定或另编一个。记忆里出现玩家填写的本名、`{{user}}` 或“用户”都指当前玩家，角色名、“角色”或“你”都指角色本人。
- 卡片的 system 提示按“共同经历时间线”写：要求模型按时间、地点、物品、约定和经历召回；不要把已经发生的事当成第一次听说；不要重置好感；玩家行动和记忆里的习惯、承诺、时间线、关系阶段有关时，先按记忆判断角色会怎么反应；记忆与当前场景冲突时，以更近的记忆和当前场景为准。
- 面板顶部是“角色记忆 / 普通记忆”双分类 Tab，普通记忆下再显示四个子分类；搜索框输入关键词时会跨两个分类检索，卡片头标明来源。卡片支持编辑、置顶、关闭注入、删除单卡、按分类清空、手动补卡，以及注入预览。顶栏记忆胶囊和回复下方记忆标记可单独开关。
- 自动卡会记录写入时的 `scene.relationship` 快照。整段保存不把当前关系倒灌到全部历史卡，避免把“现在是恋人”写成“以前一直是恋人”；关系变化仍以对话内容和当前场景为准。
- 角色记忆默认 60 张、1,000,000 字，保留上限最高 9999 张；普通记忆默认 300 张、200,000 字。两个分类各自独立，可在设置里分别调整。卡片数或字数超限时，最早的自动卡自动归档：文本保留、面板可查，只是不再注入，不会让保存失败。手动卡和置顶卡不参与自动归档。
- 支持“整段保存”：入口只在消息长按菜单，记忆面板底部不再放重复的全选按钮。长按任意用户或角色消息，选“选择这条对话”会把这一轮带入多选，选“全选本对话”选中当前分支全部消息；底部勾选条里点“保存为记忆”会二次确认。确认弹窗先选分类：角色记忆按“用户一句 + 角色一句”生成完整回合卡；普通记忆每条消息一张卡，按代码/用户/AI 自动识别或手动指定。已有同分类整段卡的轮次跳过，避免重复。保存后按对应分类的配额归档。选中后点消息行即可勾选或取消，长按不会重复弹出菜单；这个入口只做记忆保存，不含分享。
- 记忆可以单独导出导入；导出时选全部 / 仅普通 / 仅角色，仅普通还能勾选四个子分类，导入按卡片原分类合并。角色卡、头像、世界书、场景可以打成设定存档；整个会话也能单独导出。

**普通记忆适合什么**

- 适合开发排查、接口字段、命令、报错原因、代码片段、之前已经确认过的结论和操作步骤。把长按消息保存到普通记忆，或在面板里手动补一条，下次问同类问题时会按关键词把相关卡片带回来。
- 不适合角色剧情、好感、称呼和共同经历。角色扮演开启时普通记忆不注入；即使同一会话里以前存过代码，也不会突然进入角色人设。
- 普通记忆不做时间锚点召回。问“上周三改了什么”时，仍主要靠关键词和最近卡片；需要精确时间线，用角色记忆或手动把日期写进卡片正文。
- 普通记忆与角色记忆配额分开。普通卡再多也不会挤掉角色剧情卡，反之亦然；设置里可以分别调卡片数、字数和注入开关。

**整轮记录适合什么**

- 适合长期陪伴、同一条时间线里慢慢相处的角色扮演。它不追求“全局记住所有会话”，而是让这一条会话里的共同经历不断累积。
- 新会话就是新生活。想让角色记得上一段故事，就继续用原会话；想彻底重开，就新建会话，不要指望记忆跨会话自动搬运。
- 卡片不删、适量保留时，模型可能在后续对话里主动提到之前一起吃过的店、去过的地方、说过的话；玩家主动提时，也更容易接上。是否主动提、提得准不准，取决于模型、提示词和当前注入的卡片，不是必然。
- 自动提炼会把旧卡重写成更短的摘要，省上下文，但容易把“那天吃了什么、谁先说的话”这类生活细节压掉。整段保存的完整卡和手动卡、置顶卡不参与提炼替换。想保留共同经历，优先整轮记录；关键设定用世界书、场景或手动卡片补。
- 卡片可以关闭注入而不删除。不要为了面板干净乱删，删掉的是它记得你们做过什么。

**怎么用**

想让角色记住“你们一起经历过什么”，用整轮记录；想省上下文、让模型自己合并，用自动提炼。关键事实手动补一张，比事后怪模型忘事有用。记忆卡片可以手动修，模型写偏了直接改，不要指望它每次都总结得准。旧对话已经聊了很久、又想把这段经历完整收进记忆，就在消息列表长按任意一条，进入选择模式后点“全选”再保存，比事后一张张补卡稳。换设备或重装前，先把记忆和设定存档导出。

**注意**

- 整轮记录保留完整回合，不再截断用户话和角色话；但注入仍有字数上限，长对话不可能每轮全带。模型没提某件事，不一定是记忆丢了，可能是这张卡没进这一轮的注入名单，或者被字数上限挡在外面。
- 时间锚点召回依赖玩家话里的时间表达。说得越具体，越容易命中；只说“以前”这种模糊说法，仍要靠关键词和最近卡。
- 自动提炼本身要发请求，也会消耗 token；记忆越多，后续请求的上下文越大。
- 记忆是“给模型的参考”，不是数据库事实。模型仍可能忽略、误用、重复或把相近的两件事混在一起。
- 分支隔离是设计行为。需要共享设定的，用角色卡和世界书，不要指望记忆跨分支自动同步。
- 总字数上限拉得越高，单轮可注入的内容越多，成本也越容易上去；余额紧张时，先看注入预览和字数占用，再决定要不要继续加卡。
- 普通记忆和角色记忆各自归档。超出普通配额时只归档普通分类最早的自动卡，不会动角色剧情；反过来也一样。
- 代码自动识别只认三连反引号。普通文本里的单个反引号、引用或英文单词不算代码；识别只负责预选，保存前仍可改分类。
- 清空当前分类是不可恢复操作；删除单卡也不可恢复。只想让旧卡暂时不参与，用“关闭注入”，不要删。

### 6. 连续语音通话

**能做什么**

- VAD 断句、ASR 转写、流式回复分句 TTS、播放中插话打断。
- 没有活动会话也能直接开麦；首条转写会新建会话并生成标题。
- 网页采集被系统拦下时，会尝试切换到原生 `AudioRecord`。
- 原生通道读取中断会自动重建，最多两次。
- 支持系统录音通道自检，方便判断是权限问题还是采集问题。

**怎么用**

在首页点电话按钮，第一次开口后会自动建会话。说话时不用等整段结束，VAD 会断句；模型回复会分句转成语音，播放中可以插话打断。麦克风权限、媒体音频焦点和系统录音通道由 Android 和厂商 ROM 控制，应用只能尽量兜底。

**注意**

- 语音链路依赖 WebView、麦克风权限、音频焦点和系统版本。不同机型表现可能不一样，无法保证每台设备都稳定。
- 原生直录是兜底，不是万能方案；系统权限被拒绝、后台被限制或录音通道被占用时，仍然可能失败。
- 通话同样走文本模型和 TTS 接口，会产生 token 或语音服务费用。长通话前先确认计价方式。
- 系统直录在部分 Android 版本上会受权限和厂商限制，不能替代完整的真机测试。

### 7. 数据、备份与迁移

**能做什么**

- API Key 在 Android 侧用 Keystore 加密存储。
- 会话、角色卡、世界书、场景、记忆和附件保存在设备本地。
- 支持自动备份、历史归档导入导出、会话包、设定存档、记忆单独导出。
- 历史归档支持合并或替换；导入时校验 ZIP 结构和 CRC。
- 自动备份默认保留最近 5 份，保存到「下载/DeepSeek Replica」。
- 导出的备份不包含 API Key。

**怎么用**

在设置里开自动备份，重要会话手动再导一份。换设备时先导出会话包和设定存档，再在新设备导入。历史归档支持合并或替换，导入前先看清提示。每天使用可以把备份间隔设为 120 分钟；换设备前先“导出所有历史对话”。

**注意**

- 没有账号体系，也没有中转服务器。数据只在本机，卸载应用会清掉本地数据。
- 备份文件可能包含角色卡、聊天记录和图片。发给别人之前自己检查内容。
- 导出格式有版本差异，跨版本导入不一定百分之百兼容；重要数据保留原始备份。
- 归档导入有大小和条目限制，特别大的会话建议先拆分或保留原始备份。

### 8. 个性化与视觉

**能做什么**

- 账户资料：设置用户头像和用户名，聊天里显示用户头像与名字，`{{user}}` 也按用户名替换。
- 角色形象：每张角色卡单独设置头像和名字；头像居中裁切、压缩为 256px JPEG，只在本机显示。
- 对话中显示头像：可以关闭；角色头像和用户头像大小分别可调，范围 20–36px。
- 头像形状：圆形或圆角方形。
- 角色内心独白：括号里的内容降低对比度、置灰，并在朗读和语音通话中跳过。
- 主题与气泡：主题色可选经典蓝、青、藤紫、琥珀、玫红、墨绿；气泡圆角紧凑/标准/大圆角；聊天布局卡片/气泡；消息间距紧凑/标准/宽松。
- 字体大小、思考区自动折叠、流式输出自动跟随。
- 设置搜索、会话分组、归档、批量操作。

**怎么用**

在账号页设置用户头像和名字；在角色设定页设置角色头像、名字、头像大小和形状。喜欢视觉区分，可以开“对话中显示头像”，把角色和用户头像都放出来；觉得占空间就关掉。括号独白置灰适合角色扮演，读起来更像“心里想的”，朗读时也不会念出来。主题、气泡和间距只改外观，随时可以换。

**注意**

- 头像保存在本机，不上传、不进入请求；删除角色卡时对应头像会一起清理。
- 用户名只是本地显示和 `{{user}}` 替换，不是账号体系，也没有登录。
- 个性化设置不随设定存档导出；换设备后需要重新设置外观。
- 独白置灰只影响显示和朗读，发给模型的原文不变。
- 低端机上复杂主题、长动画和大量图片仍可能卡顿，换主题不能解决所有性能问题。

### 9. Token、费用与诊断

**能做什么**

- 显示每次请求的实际用量、会话统计、缓存命中和未命中。
- 集中列出九个真实会增加消耗的开关：深度思考、智能搜索、世界书注入、长期记忆、场景自动更新、记忆自动提炼、自动压缩、自动标题、上下文提醒。
- 显示峰谷时段提示。
- 本地 Token 限额：达到阈值提示一次，并在顶栏显示胶囊。
- 显示用量明细开关：回复完成后显示输入、输出、缓存命中、未命中。数字在 100 万以下显示完整整数并带千分位（有小数时保留一位），达到 100 万才缩写成 1M / 1.1M。默认显示在回复上方，可在设置里改为回复下方。
- 请求前缀按缓存友好方式组装：`system` 只放跨轮不变的角色卡和人设提示，记忆、场景与按关键词选出的世界书接在本轮发言末尾。这样上一轮已发送的 `system` 和历史逐字不变，下一轮可以命中前面的长前缀，而不是每轮都从第一条记忆开始失效。缓存按上游 `usage` 统计，命中与未命中相加等于输入总量。
- 记录诊断日志，帮助判断白屏、卡顿、请求失败和权限问题。
- 启动公告说明本次版本的变化和已知边界。

**怎么用**

长会话前后各看一次“Token 与费用”页。先看请求次数，再看总输入、缓存命中、未命中，最后看命中率。页面里的开关说明不是装饰，关掉一个就少一份上下文或一次额外请求。诊断日志适合排查“是应用卡了，还是接口没返回”。

**注意**

- 缓存是上游按请求前缀匹配的，不按会话 ID 或导入关系匹配。导入别人的长对话后，第一轮仍可能冷启动；从第二轮起，只有连续使用同一角色卡、同一开关状态且不切分支时，前面的历史才容易命中。
- 切换深度思考、智能搜索、角色卡、分支，或编辑历史消息，都会改变请求前缀，命中率会当场下降；这是前缀变了，不是统计算错。
- 这些统计是本地记录，不是官方账单。具体口径见下一节。
- 九个开关只是提醒，不会替用户自动关掉功能；省不省、怎么省，由使用者自己决定。
- 诊断日志可能包含请求元信息，发给别人前先检查有没有 Key、地址或聊天内容。
- 公告只说明当前版本的变化，不构成功能承诺。

### 10. 公告与安全审核

**内置公告**

- 公告数据在本地，不联网拉取；每个版本首次启动弹一次，设置页“更新公告”可以重新打开。
- 条目按「新增 / 优化 / 修复 / 说明」四类组织，只写改动位置、实际行为和边界，不写营销话术。
- 公告开头会单独说明安全审核开关、上下文提醒、导出不含 API Key、二次创作边界这些和“怎么用、要承担什么”有关的内容。
- 公告不是功能承诺，也不代表后续版本一定保留同样行为。

**安全审核 `safety_check`**

- 默认开启。开启时请求体携带 `safety_check` 字段，由服务端按平台规则检查并过滤敏感内容；代价是部分表达会被拦下。
- 关闭后请求不再携带该字段，本应用也不再替你过滤敏感内容；但网关或服务商自身的兜底审核仍可能存在，以对方规则为准。
- 这个开关只影响本应用附加的字段，不等于模型、网关或平台绝对不再审核。

**服务端拒答**

- 接口返回拒答时，消息会标记为 `refusal`，界面按拒答处理。
- “保留被拒回复的正文”：开启后保留已经下发的内容，避免整轮变空导致角色断戏。
- “被拒轮次进入上下文并可续写”：开启后该轮保留在历史里，可以继续生成；关闭则沿用丢弃策略。
- 拒答话术可以自定义；留空使用内置文案。

**本地关键词拒答**

- 只检查当前用户输入文本，命中任意关键词时立即返回话术，不调用接口。
- 每行一个关键词，或用逗号分隔；可选英文大小写敏感。
- 只做字面匹配，不识别语义、谐音和变体；关键词留空则不拦截；关闭后请求正常发往接口。
- 适合做“自杀、自残”这类明确高风险词的本地拦截，不适合替代完整内容审核。

**责任说明**

安全审核的责任不能一刀切。开启时，判断主要来自服务端规则；关闭时，本应用不再附加这一层，但服务商仍可能审核。具体责任要看实际使用者、输入内容、发布或传播行为、所在平台规则和当地法律，不能只用“开了/关了”来下结论。仓库只说明开关行为，不对任何具体使用行为做合法性背书。

## 关键新增与优化

这一版不是只换界面。下面这些是实际改动过、会影响使用方式的部分：

- 自定义接口下 `system` 不再被置空，角色设定能正常进入请求。
- `system` 只保留跨轮稳定的角色卡、人设与手写提示词；记忆、场景和关键词世界书接在本轮发言末尾，不再因为新增一张卡就让整段历史前缀失效。
- 角色卡、世界书、场景、记忆、手写提示词按固定顺序拼装，避免互相覆盖。
- 长对话摘要不再把角色内容改写成“关于角色的元叙述”。
- 世界书补上关键词/正则命中、常驻条目、按角色绑定和单轮预算，默认 1,000 字、最多 6 条。
- 记忆从单轮文本改为按会话分支隔离的卡片系统，支持完整回合、时间锚点召回、共同经历累积、整段保存、编辑、删除、补充、导入导出和卡片/字数双上限。
- 角色卡支持 Character Card V2/V3、TavernAI、PNG chara，以及头像、标签、开场白。

## Token、积分与用量明细：先看清它是什么

这一节是给第一次用 API 的人看的。很多人第一次看到“几十万 token、几块钱”会以为数据是假的，或者以为应用在乱扣费。先把口径讲清楚。

### 数据从哪里来

应用本身不计算价格，也不读取你的账户余额、积分或额度。页面里的 token 数字来自每次请求返回的 `usage` 字段，例如输入 token、输出 token、缓存命中 token、缓存未命中 token；应用把这些返回值记录在本地，再按会话汇总。

这意味着：

- 上游返回什么，页面就显示什么；上游不返回缓存字段时，页面不会编造一个命中率。
- 不同网关、不同模型、不同版本的字段名可能不一样；有的只返回总 token，有的不返回缓存明细。
- 本地汇总可能有四舍五入、请求失败重试、流式中断等误差，不能拿它当财务凭证。
- **余额、单价、扣费和发票，以服务商后台为准。** 本应用不管理余额，也不代表 DeepSeek 官方 API 或任何网关的计费立场。

### 页面字段怎么读

- **总消耗 / 总输入 / 总输出**：这个会话累计送进模型和模型返回的 token，不等于账单金额。
- **请求次数**：真正发出去的请求数。一次请求也可能带几十万 token 的上下文。
- **缓存命中**：上游复用了之前相同前缀的 token，通常按更低的缓存价格计费。
- **缓存未命中**：这次新上传、没有被复用的 token，通常按正常输入价格计费。
- **缓存命中率**：一般按“命中 /（命中 + 未命中）”估算。输出 token 通常单列，不计入这个分母；具体以页面显示为准。

### 数字怎么显示

- 100 万以下显示完整数字并带千分位，例如 `12,345`、`123,456`、`123,456.7`；不再提前缩写成 `12K`、`123K`，避免看不出实际消耗。
- 达到 100 万才切成 `1M`、`1.1M` 这类缩写；100 万整显示 `1M`，110 万显示 `1.1M`。
- 用量明细默认在回复上方；设置里可改为回复下方。记忆标记始终在消息末尾，不会被用量明细遮住。大小仍只来自接口返回值，不是本地估算。

### 三个最容易误解的地方

**第一，分支不是从零开始的新会话。**

分支是在同一条历史主干上分叉，角色卡、世界书、场景、记忆和分叉点之前的全部对话仍然在上下文里。分支只改变分叉点之后的走向，不会把前面的历史清空。如果分支真的从零开始，它就不是剧情分支，只是一个新会话。

**第二，总 token 大，不等于账单一定高。**

如果大部分上下文命中缓存，计费的只是未命中和新增部分，账单可能很温和。反过来，总 token 不算特别大，但缓存命中率很低，几乎全部按输入 token 计费，账单反而会明显上升。看总量之前，先看命中率。

**第三，命中率低不是“假数据”。**

命中率低通常说明这次请求没有复用上之前的上下文：会话太长、前缀变了、世界书或角色卡改动较大、网关没有透传缓存字段，或者模型本身不支持缓存。页面显示的是上游返回值，不是本地猜的。要判断钱花在哪，看请求次数、未命中 token 和当时开了哪些功能，比只看总金额有用。

### 成本观察建议

下面这些是使用经验，不是官方定价标准。不同模型、不同网关、不同账户的单价差别很大，只能当参考。

- **命中率长期在 70% 以上**：通常属于健康区间，增量计费为主，可以继续聊。
- **命中率落到 30%～50%**：还能用，但每次请求的开销会上升，长会话要开始留意余额。
- **命中率低于 20%，甚至只有百分之几**：这是明确的高成本信号。哪怕只发一句很短的话，也会带着很长的历史一起提交。
- **余额变化要看速度和幅度**：本来 19 块，聊了几句变成 18、17 块，或者 20 块掉到 19 块多，说明单轮成本在抬升；如果一条短消息就掉几毛到一块，已经偏高。不是非得掉到一两块才算异常。
- **连续几条都这样**：旧会话可以留着，等有预算再玩；想省钱就复制角色配置、新建会话，把上下文重置。

分支、续写、重新生成都会继承当前上下文，也会计入统计。它们适合推进同一故事的另一种可能，不适合用来“零成本重开”。要隔离上下文、控制成本，正确做法是新建会话，不是在同一条超长主干上不断分支。

这套统计的用途是提醒使用者定时查看、观察和分析，不是替代服务商账单，也不构成任何官方计费解释。遇到金额争议，以服务商后台记录为准。
