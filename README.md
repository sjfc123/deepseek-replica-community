## 源码组织与功能分区

当前源码按“功能优先”组织，便于阅读者先定位职责、再阅读实现：

- 每个手写源码文件的顶部都有 `功能区：<模块> / <文件> 开始`，底部有对应的 `结束` 标记；文件头同时写明职责范围和对外导出。
- 复杂模块内部再按业务边界拆分，使用 `功能区：<子功能> 开始/结束` 标记。例如聊天状态机按状态持久化、会话装载、消息生成、记忆、附件与流式请求拆分；设置页按通用控件、状态派生、页面分发、弹层与页面栈拆分；角色卡面板按字段模板、筛选派生、卡操作、世界书/导入导出、编辑器与主渲染拆分。
- Android 原生层同样分区：WebView 生命周期、返回键与系统栏、资源拦截、权限与媒体入口、JS 桥、录音与通话采集分别标注。
- `*.module.css.d.ts` 等生成文件不手工插入分区注释，避免下次生成时被覆盖。
- 注释用于说明职责、输入输出、兼容边界和副作用，不重复描述显而易见的赋值语句；历史迁移逻辑会明确标注“仅用于升级读取”，避免被误认为当前主路径。

分区标记示例：

```text
/* -------------------- 功能区：会话持久化 开始 -------------------- */
// ...相关实现...
/* -------------------- 功能区：会话持久化 结束 -------------------- */
```


0.8.87 源码相对 0.8.86 发布版存在行为变更：新装默认为普通 DeepSeek AI 助手，仅在启用角色卡或基础档案时进入角色上下文，且同一时间只读取一张卡。0.8.86 的 APK 不包含这些改动；使用新行为需按当前源码构建。

## 基本使用流程

1. 按“构建”一节自行编译，或使用可核验的构建产物。仓库不附带签名文件。
2. 打开设置，填入 API Key、接口地址和模型名；按服务商要求选择 Chat / Responses / Anthropic / 自定义网关。
3. 先发送一条普通消息，确认默认助手行为与接口返回正常；默认配置不会进入角色扮演。
4. 进行角色扮演时，新建或导入角色卡，按需绑定世界书并填写场景；同一时间只启用一张卡，也可改用基础档案或自行改写提示词。
5. 长对话前检查“Token 与费用”页，确认会增加的消耗项。
6. 重要会话、角色卡和设定，定期导出备份。卸载应用会清掉本地数据。
7. 出现白屏、闪退或麦克风不可用等问题时，先查看诊断日志，再区分应用、系统权限和接口网关。

## 功能详述

以下按功能域说明用途、入口和限制。功能覆盖范围不代表每个模块都经过同等程度的验证。

### 1. 模型与接口

#### 功能范围

- 支持 Chat Completions、Responses、Anthropic 和自定义网关等请求形态。
- 本地模型可接 Ollama、LM Studio、vLLM、LocalAI 一类兼容端点。
- 支持自定义请求头，格式为多行 `Key: Value` 或 JSON 对象；同名请求头会覆盖内置值，包括 `Authorization`。
- 支持回复菜单里的“生成配图”，可设置绘图模型名和图片尺寸，默认模型 `gpt-image-1`、默认尺寸 `1024x1024`。
- 自定义接口下不再把 `system` 整个置空：角色卡（没有卡时为手写基础档案）、表达提示词和固定演出规则进入 system；记忆、场景和当前轮次世界书进入当前 user 消息的尾部。完整装配见 [SYSTEM-PROMPT-PIPELINE.md](SYSTEM-PROMPT-PIPELINE.md)。

#### 使用方式

在设置中选择接口类型，填写地址、Key 和模型名。第三方网关要求额外鉴权时，在自定义请求头中填写 `Authorization: Bearer <key>`；网关不支持 DeepSeek 扩展字段并返回 400 时，应关闭 `safety_check` 和 `latest_reminder` 后重试。确认普通消息可正常返回文本后，再启用角色扮演和附件。

#### 限制与注意事项

- 不同网关对字段支持不一致。部分端点会忽略图片、工具调用、搜索或 `reasoning` 参数；该行为来自上游实现，并非前端丢弃参数。
- 自定义头会覆盖同名默认头。`Authorization` 写错会导致请求失败，格式错误的请求头行会被忽略。
- 本地模型的上下文长度、显存和并发能力由使用者本机配置决定。
- 生成配图使用独立的图片接口；支持情况与计费方式由服务商决定，部分网关不提供该接口。

### 2. 生成参数与请求

#### 功能范围

- 通用采样：温度 `temperature`、Top P、最大输出 tokens；留空表示不发送，沿用服务端默认值。
- 角色扮演采样：单独一套温度、Top P、最大输出；启用角色卡时优先使用，未填写的项继承通用值。
- 推理强度：`thinkingEffort` 可选 low / high / max，仅在 OpenAI 协议且开启深度思考时下发 `reasoning_effort`。
- 上下文提醒 `latest_reminder`：在当前 user 之前附带日期、星期、大致位置、`Web` 和语言快照；与上一条内容相同不重复插入；自定义接口默认不发，隐私敏感或需要完全虚构时间线时可关闭。
- 服务端自动生成标题：首轮请求携带 `title` 字段；关闭后由首条消息文本生成标题。
- 安全审核 `safety_check`：开启时请求体携带该字段，由服务端按其规则检查；关闭后不再发送该字段。
- 本地 Token 限额：达到设定值提示一次，并在顶栏显示胶囊；只读接口返回的 `usage`，不改变服务端计费上限。

#### 使用方式

日常问答通常使用较低温度；角色扮演常用温度为 0.8–1.1、Top P 为 0.9–1。回复偏离主题时应降低温度；句式重复时可小幅上调温度或降低 Top P；回复被截断时应提高最大输出。角色卡启用时优先使用角色扮演参数；无需单独设置 Top P 和最大输出时可留空。

#### 限制与注意事项

- 参数范围由模型决定。温度一般 0–2、Top P 0–1、最大输出 1–1,000,000，但超出接口范围会被拒绝。
- 留空表示不发送该字段；填 0 表示明确发送 0。两者含义不同。
- `latest_reminder` 会带大致位置，不需要就关掉。
- `safety_check` 是请求字段，不是本地过滤器；关闭仅表示本应用不再附加该字段，服务商仍可能执行审核。
- 自定义网关不支持扩展字段时，应先关闭 `safety_check` 和 `latest_reminder`，不应直接修改代码。

### 3. 日常聊天

#### 功能范围

- 渲染 Markdown、表格、代码块、KaTeX 公式和 Mermaid 图表。
- 支持图片、文件附件，支持联网搜索，支持回复朗读。
- 支持重新生成、创建分支、编辑用户消息、编辑模型回复、复制、删除单条消息、长按菜单。
- 支持会话分组、归档、批量操作、删除会话。
- 支持主题色、气泡样式、消息密度、设置搜索、字体大小。
- 支持完整性校验的自动备份、历史导入导出、会话包导出。
- 支持自动压缩、自动标题、上下文提醒和 Token 限额提醒。

#### 使用方式

在设置中选择接口类型和模型，填写 Key 与地址后返回首页发送消息。需要对比回答时使用“重新生成”；需要保留原回答并推进另一条剧情时使用“分支”；需要修正使用者或模型消息时使用“编辑”；不再使用的会话可归档或删除。附件和联网搜索会增加请求 token，长对话前应确认接口是否支持对应字段。

#### 限制与注意事项

- 分支继承分叉点之前的全部上下文，与新会话不同。分支数量增加会延长后续请求的历史。
- 编辑模型回复会改写该条消息并影响后续上下文；删除消息也会改变历史。操作前应确认影响范围。
- 附件、搜索结果和长历史都会进入上下文。功能可用不代表单轮成本较低。
- 主题、气泡和字体只影响显示，不影响请求内容。
- 自动压缩和自动标题可能产生额外请求，具体取决于当前实现与开关状态。

### 4. 角色扮演

#### 功能范围

- 默认不启用角色扮演：新装、恢复默认或从未修改提示词时，system 为普通 DeepSeek AI 助手，不含人物口吻。进行角色扮演时，需启用角色卡、填写基础档案或改写表达提示词。
- 角色卡最多 50 张，同一时间只允许一张全局启用卡；没有有效卡时角色扮演开关不会开启，避免多张卡同时污染 system。支持自定义头像、标签筛选、开场白；内置大肥鱼、鲸鱼娘、猫娘，以及江湖顾长风、修仙云岫、都市许棠六张卡。
- 设置根页的「角色档案与表达」为手写角色入口：先填写角色基础档案，再设置头像、显示和表达提示词。基础档案 32 项、分四组：基本档案（年龄、性别、代词、种族、生日、职业、居住地、语言与口音、出处与身份）、身体与生活（身高、体重、外貌、喜欢的食物、讨厌的食物、常喝的、兴趣、日常作息、随身物、宠物）、性格与边界（性格底色、价值观、雷点、底线、配合方式）、剧情与表达（过往经历、与对方的关系、当前处境、目标与动机、弱点与恐惧、说话方式、秘密、补充设定）。角色名字单独保存，不计入 32 项。档案开关默认开启；关闭后 32 项字段不再读取、不再进入 system，字段变灰只读；非空档案名仍以轻量身份行保留，重新开启才能编辑完整档案。
- 角色卡可填完整固定参数与生活细节：年龄、性别、代词、种族、身高、体重、生日、职业、居住地、语言与口音、喜欢的食物、讨厌的食物、常喝的、兴趣、日常作息、随身物、宠物、性格底色、价值观、雷点、底线、配合方式；再填题材、玩法、身份、外貌、关系、过往经历、情景设定、当前目标、说话方式、小习惯、秘密、补充设定、开场参考、对白示例和系统指令。补充设定不限字数。玩法提供沉浸对话、群像叙事、悬疑调查、经营养成、冒险推进五套演出指引；题材给出日常、江湖、武侠、修仙、都市、校园、职场、悬疑、科幻、奇幻、历史、末世、宫廷、军事、无限流、克苏鲁建议，也可自行填写。
- 支持导入 Character Card V2/V3、TavernAI 和 PNG chara；`scenario`、`system_prompt`、`post_history_instructions`、`mes_example` 会分别进入情景设定、系统指令和对白示例。
- 世界书最多 100 条，支持关键词或正则命中、常驻条目、按角色绑定、单轮预算；新增世界、人物、地点、事件、规则、物品、线索、组织、关系等分类，正文上限 4,000 字。默认单轮 1,000 字、最多 6 条，可按 500–20,000 字调整。
- 世界书条目可选「最近发言」或「整段历史」扫描，并可为每条填写避触词：命中避触词时整条跳过，适合防止已经过去的误会、死亡或旧状态被反复召回。
- 世界书条目带可信度：硬设定、局部事实、传闻。硬设定不能被对话推翻；局部事实只在其范围内成立；传闻可能不准确，也可能只是某人的说法。完全重复的条目（同角色、同分类、同可信度、同标题、同正文）在保存和加载时会合并，只清完全重复，不误删多版本设定。
- 支持导入 SillyTavern 世界书和 `character_book` 一类条目，分类、扫描范围与避触词一并读取。
- 场景从时间、地点扩到天气、穿着、心情、关系阶段、氛围与感官、在场人物、当前目标、冲突与悬念、关键物件；可手填，也可按轮自动提取。
- 角色表达支持内心独白、动作样式、`{{user}}` / `{{char}}` 占位符、玩家括号独白、称呼约定和长消息折叠。
- 支持“压制「按设定」这类元叙述”：在 system 末尾追加强制约束，不提及规则、不复述设定、不分析用户意图、不使用 AI 视角评述。
- 最终 system 分两种：普通对话只有默认 DeepSeek 助手提示；启用角色卡、基础档案或身份行时，人物层三选一，默认助手提示换成中性角色基底，再拼自定义提示词和按需追加的演出规则。档案开关关闭时不再读取 32 项档案字段，但非空档案名会以轻量身份行保留；记忆、场景和当前轮次世界书不进入 system，而是接在当前 user 消息末尾。完整装配与缓存边界见 [SYSTEM-PROMPT-PIPELINE.md](SYSTEM-PROMPT-PIPELINE.md)。
- 当前轮次人物优先读取会话绑定：角色卡开启时创建的会话会记住人物 id，即使之后关闭全局开关，这条会话仍按原卡身份、世界书、场景和角色记忆继续；关闭只影响新会话。旧会话没有 id 时，会按首条助手消息与卡内开场白匹配恢复。
- 关闭角色扮演后，新会话不再注入角色卡；如果档案开关开启且填了手写基础档案，仍按档案里的身份继续，表达提示词照常发送。已绑定人物的旧会话不会切换为普通助手。档案开关与角色扮演是两个独立开关：档案关闭只停 32 项档案字段，姓名身份行仍保留，不会同时关闭角色卡；关闭角色卡也不会修改档案开关。

#### 使用方式

默认配置可直接用于普通问答，无需创建角色卡。进行角色扮演时，创建或导入角色卡，并按需绑定世界书。角色卡定义人物身份、与 {{user}} 的关系、说话方式和开场局面；世界书定义地点、组织、规则与历史；场景定义当前时间、地点、在场人物、目标和冲突。世界书条目不宜过多：常驻条目每轮进入上下文，按关键词命中的条目开销更低。需要长线设定时，可为条目选择「整段历史」并填写避触词，避免已解决事件重复出现。场景可手写，也可由应用按轮提取；自动提取仅修改发生变化的字段。

未准备角色卡，或使用自建 OC、二创、游戏、动漫、小说角色时，先在「角色档案与表达」填写基础档案，再编写表达提示词。基础档案按四组顺序写：基本档案 → 身体与生活 → 性格与边界 → 剧情与表达。年龄、性别、代词、种族、生日、职业、居住地和语言应尽量填写完整；这些字段缺失时，人物参数最容易在对话中发生漂移。字段越具体且前后一致，人物约束越稳定；仅使用“温柔、高冷、神秘”等抽象标签时，约束通常较弱。档案仅描述人物本身，不写剧情大纲、系统规则或“请扮演”指令。档案开关开启且没有当前人物卡时，档案进入 system；有当前人物卡时以卡为准，不叠加。关闭档案开关后，32 项档案字段不读取，表达提示词独立生效；非空档案名仍作为身份行保留，两套身份不会互相改设定。

#### 配置示例

1. **夜班便利店**
   - 角色卡：你是{{char}}，28 岁，夜班便利店店员。对{{user}}克制但关心，称呼“你”。用对话和动作推进，不复述设定，不替{{user}}决定行动。
   - 世界书：标题「便利店仓库」，关键词「仓库、后门」，正文「后门锁坏，只有店长知道」。
   - 场景：凌晨两点，便利店仓库门口，{{user}}刚下夜班。

2. **雨夜旧港侦探**
   - 角色卡：你是{{char}}，落魄侦探，说话短、观察细，不主动解释自己的过去。
   - 世界书：标题「旧港区」，关键词「码头、雨夜、失踪」，正文「三年前这里沉过一艘没有登记的货船」。
   - 场景：暴雨，旧港区码头，{{user}}带着一张被雨水泡皱的照片。

3. **日常陪伴**
   - 角色卡：你是{{char}}，住在{{user}}隔壁的猫娘室友，语气轻，偶尔撒娇，但有自己的生活节奏。
   - 世界书：标题「冰箱贴」，关键词「晚饭、冰箱、超市」，正文「冰箱上贴着上周的超市小票，背面写了购物清单」。
   - 场景：周末午后，厨房，{{user}}刚打开冰箱。

#### 限制与注意事项

- 角色一致性取决于模型、角色卡写法和上下文长度；应用按固定顺序装配设定，不保证具体演出效果。
- 角色卡与世界书均由字段拼装，描述应具体、可执行。外貌、过往和目标宜写具体事实，系统指令宜写明确规则；抽象形容词对稳定性的作用有限。
- 基础档案只描述人物本身。写“请扮演”“不要出戏”“按设定回答”这类规则，应该放表达提示词；写剧情大纲、章节安排，应该放对话或世界书。
- 基础档案在有当前人物卡时不叠加：会话绑定卡和当前启用卡优先，档案仅作为无卡时的身份来源。停用完整档案时，应关闭「读取基础档案」开关；关闭后 32 项字段变为只读、不再读取，但姓名仍作为轻量身份行保留。该机制可避免角色卡、档案和提示词同时改写人物设定。
- 世界书常驻条目、整段历史扫描、自动场景提取、记忆自动提炼都会增加请求量。角色卡越细、世界书越长，成本越高。
- 长消息折叠只是显示层处理，不会减少送进模型的内容。
- 关闭全局角色扮演只影响新会话；已绑定人物的会话会继续注入卡身份、世界书、场景和角色记忆。要使一条会话恢复普通模式，需新建会话。
- 补充设定不限字数，但每轮都会随卡进入 system；补充设定过长时，应提前确认上下文预算。
- 示例设定仅用于说明写法；他人的角色卡、世界书或付费设定不应直接公开分发。

### 5. 长期记忆

#### 功能范围

- 长期记忆分两个顶层分类：**角色记忆**与**普通记忆**。旧版卡片没有分类字段，统一按角色记忆处理；原文、时间线、置顶、归档和注入顺序都不改。
- **角色记忆**继续走完整回合卡、时间锚点召回、好感与共同经历逻辑；**普通记忆**是开发与问答知识库，分成对话、代码、用户说的话、AI 说的话四个子分类，每条消息独立成卡，不强行合成回合。
- 普通记忆按关键词检索，不支持时间线、好感或关系阶段召回；手动卡和置顶卡优先，其余按与当前问题的词块重合度取卡。角色扮演开启时不注入普通记忆，避免代码、开发日志污染人设；同时普通记忆暂停写入，长按保存与手动补卡都锁定角色记忆。
- 消息长按保存的二次确认弹窗可以选择“角色记忆”或“普通记忆”。普通记忆下可选自动识别、对话、代码、用户原话、AI 原话；三连反引号代码块自动预选代码分类，单行单个反引号不算代码，最终分类仍可手改。
- 非角色扮演对话里，回复出现三连反引号代码块时自动存一张普通-代码卡；角色扮演开启时不走这条自动入库。同一条回复只记一次，可在面板关闭或删除。
- 普通记忆与角色记忆各有独立卡片上限、字数上限与注入开关。默认普通记忆 300 张、200,000 字，角色记忆 60 张、1,000,000 字；角色记忆卡片上限最高可调到 9999 张，两个分类都可以在设置里改。
- 记忆按会话分支隔离：换一个新会话，旧会话的记忆不会跟过去；从旧消息分叉，会继承分叉点之前的卡片。分支继承分叉点之前的同一条时间线。
- 支持关闭、整轮记录、自动提炼三种角色记忆模式。整轮记录不额外发请求；自动提炼会额外发一次合并请求。
- 整轮记录改成完整回合卡：用户原话和角色回应都保留，不再压成前 120 / 180 字；卡片头部写入时间、轮次和记录时的关系阶段，正文按“用户 / 角色”分段。每张卡对应一段可回看的完整经历，而非单句摘要。
- 卡片挂在这一轮的消息上，跟着当前会话和分支走。一轮轮累积下来，会形成“我们一起做过什么、说过什么、关系走到哪一步”的记忆链。
- 支持时间锚点召回：玩家提到“今天 / 昨天 / 前天 / 大前天 / 上周 / 上周三 / 这周 / 这周三 / 上个月 / 去年 / 前年 / 前几天 / 前阵子 / X 月 X 日 / 去年 X 月 X 日”这类时间时，命中时间范围的旧卡会进入相关名额，即使没有直接关键词也能被带进这一轮。只写“X 月 X 日”且日期落在未来时，按记忆语境回退到去年。
- 注入按“手动记录 → 置顶 → 最近 → 相关旧卡”排序。手动卡是玩家明确要求角色记住的姓名、偏好、习惯和经历，不参与最近 12 张的竞争，优先进入上下文；置顶卡最多 8 张，最近卡 12 张，和当前发言相关或命中时间锚点的旧卡最多 12 张。其余卡片留在面板和归档里，不参与这一轮。
- 手动卡优先回答已知信息：玩家问“我最喜欢吃什么 / 用户喜欢什么 / 韩寒喜欢什么 / 角色喜欢什么”这类问题时，记忆块要求模型先查手动记录和已有卡片，有明确记录就按记录回答，不要说不确定或另编一个。记忆里出现玩家填写的本名、`{{user}}` 或“用户”都指当前玩家，角色名、“角色”或“你”都指角色本人。
- 卡片的 system 提示按“共同经历时间线”写：要求模型按时间、地点、物品、约定和经历召回；不要把已经发生的事当成第一次听说；不要重置好感；玩家行动和记忆里的习惯、承诺、时间线、关系阶段有关时，先按记忆判断角色会怎么反应；记忆与当前场景冲突时，以更近的记忆和当前场景为准。
- 面板顶部是“角色记忆 / 普通记忆”双分类 Tab。0.8.71 起面板加宽到 720px 上限，整块面板可滚动：标题吸顶、补卡区吸底，在面板边框或卡片外空白处下滑也能浏览长对话。卡片头只留分类、来源和时间，已启用、置顶与编辑、删除一起放在卡片底部；底部重复的分类选择已移除，手动补卡跟随顶部当前分类，切换分类会清掉未提交草稿。0.8.72 进一步移除普通记忆顶部重复的“全部 / 对话 / 代码 / 用户原话 / AI 原话”子分类行，保留“全部 / 生效中 / 手动 / 已归档”状态筛选；底部分类只用于新卡归类，补卡输入框独占一行，添加按钮放到下一行右侧。顶栏记忆胶囊和回复下方记忆标记可单独开关。
- 自动卡会记录写入时的 `scene.relationship` 快照。整段保存不把当前关系倒灌到全部历史卡，避免把“现在是恋人”写成“以前一直是恋人”；关系变化仍以对话内容和当前场景为准。
- 卡片数或字数超限时，最早的自动卡自动归档：文本保留、面板可查，只是不再注入，不会让保存失败。手动卡和置顶卡不参与自动归档。
- 支持“整段保存”：入口只在消息长按菜单，记忆面板底部不再放重复的全选按钮。长按任意用户或角色消息，选“选择这条对话”会把这一轮带入多选，选“全选本对话”选中当前分支全部消息；底部勾选条里点“保存为记忆”会二次确认。确认弹窗先选分类：角色记忆按“用户一句 + 角色一句”生成完整回合卡；普通记忆每条消息一张卡，按代码/用户/AI 自动识别或手动指定。已有同分类整段卡的轮次跳过，避免重复。保存后按对应分类的配额归档。选中后点消息行即可勾选或取消，长按不会重复弹出菜单；这个入口只做记忆保存，不含分享。
- 记忆可以单独导出导入；导出时选全部 / 仅普通 / 仅角色，仅普通还能勾选四个子分类，导入按卡片原分类合并。基础档案、角色卡、头像、世界书、场景可以打成设定存档；整个会话也能单独导出。

#### 普通记忆适用范围

- 适合开发排查、接口字段、命令、报错原因、代码片段、之前已经确认过的结论和操作步骤。把长按消息保存到普通记忆，或在面板里手动补一条，下次问同类问题时会按关键词把相关卡片带回来。
- 不适合角色剧情、好感、称呼和共同经历。角色扮演开启时普通记忆不注入，也不能手动写入；关闭角色扮演后，角色池里带三连反引号代码块的卡不进入普通对话，只有剧情与关系卡还能参考。
- 普通记忆不做时间锚点召回。问“上周三改了什么”时，仍主要靠关键词和最近卡片；需要精确时间线，用角色记忆或手动把日期写进卡片正文。
- 普通记忆与角色记忆配额分开。普通卡再多也不会挤掉角色剧情卡，反之亦然；设置里可以分别调卡片数、字数和注入开关。

#### 整轮记录适用范围

- 适合长期陪伴、同一条时间线里慢慢相处的角色扮演。它不追求“全局记住所有会话”，而是让这一条会话里的共同经历不断累积。
- 会话之间的记忆不共享。需要延续既有经历时，应继续使用原会话；需要重新开始时，应新建会话。记忆不会自动跨会话迁移。
- 保留适量卡片时，模型可能在后续对话中提及此前的店铺、地点或对话；使用者主动提及时，也更容易衔接。是否主动提及及准确程度取决于模型、提示词和当前注入的卡片，并非必然。
- 自动提炼会把旧卡重写成更短的摘要，省上下文，但容易把“那天吃了什么、谁先说的话”这类生活细节压掉。整段保存的完整卡和手动卡、置顶卡不参与提炼替换。需要保留共同经历时，应优先使用整轮记录；关键设定可通过世界书、场景或手动卡片补充。
- 卡片可关闭注入而不删除；删除会同时移除对应记忆。不应仅为整理面板而删除卡片。

#### 使用方式

需要完整保留共同经历时使用整轮记录；需要控制上下文体积时使用自动提炼。关键事实应手动补充，记忆卡片可在生成偏离后直接修改。自动提炼不保证每次都能准确概括。需要将较长旧对话完整纳入记忆时，可在消息列表长按任意一条，进入选择模式后选择“全选”并保存。更换设备或重装前，应先导出记忆与设定存档。

#### 限制与注意事项

- 整轮记录保留完整回合，不再截断用户与角色消息；但注入仍受字数上限限制，长对话无法每轮全部注入。模型未提及某事项时，可能因该卡未进入当前轮次注入名单或超出字数上限，并不必然表示记忆丢失。
- 时间锚点召回依赖输入中的时间表达。时间表达越具体，命中率越高；仅使用“以前”等模糊说法时，仍需依赖关键词和最近卡。
- 自动提炼本身要发请求，也会消耗 token；记忆越多，后续请求的上下文越大。
- 记忆仅作为模型上下文参考，不作为数据库事实。模型仍可能忽略、误用、重复或混淆相近内容。
- 分支隔离属于设计行为。需要跨分支共享的设定，应放入角色卡和世界书；记忆不会自动跨分支同步。
- 总字数上限拉得越高，单轮可注入的内容越多，成本也越容易上去；余额紧张时，应查看注入预览和字数占用后再决定是否增加卡片。
- 普通记忆和角色记忆各自归档。超出普通配额时仅归档普通分类最早的自动卡，不影响角色记忆；角色记忆配额同理。
- 代码自动识别只认三连反引号。普通文本里的单个反引号、引用或英文单词不算代码；识别只负责预选，保存前仍可改分类。
- 清空当前分类和删除单卡均不可恢复。仅需暂停旧卡参与时，应使用“关闭注入”。

### 6. 连续语音通话

#### 功能范围

- VAD 断句、ASR 转写、流式回复分句 TTS、播放中插话打断。
- 没有活动会话也能直接开麦；首条转写会新建会话并生成标题。
- WebView 采集被系统拦截时，会尝试切换到原生 `AudioRecord`。
- 原生通道读取中断会自动重建，最多两次。
- 支持系统录音通道自检，方便判断是权限问题还是采集问题。

#### 使用方式

在首页点击电话按钮，首次开口后会自动创建会话。VAD 在说话过程中断句，无需等待整段结束；模型回复按句转换为语音，播放期间可插话打断。麦克风权限、媒体音频焦点和系统录音通道由 Android 与厂商 ROM 控制，应用仅提供有限兜底。

#### 限制与注意事项

- 语音链路依赖 WebView、麦克风权限、音频焦点和系统版本。不同机型表现可能存在差异，无法保证所有设备均稳定运行。
- 语音页身份优先使用当前会话绑定的人物；没有绑定或会话未成形时，才看全局启用的角色卡。关闭全局开关不会把已绑定的通话切回手写角色。名字仍是卡名残留时显示“语音通话”。
- 原生直录为兜底方案；系统权限被拒绝、后台受限或录音通道被占用时仍可能失败。
- 通话同样走文本模型和 TTS 接口，会产生 token 或语音服务费用。长通话前应确认计价方式。
- 系统直录在部分 Android 版本上会受权限和厂商限制，不能替代完整的真机测试。

### 7. 数据、备份与迁移

#### 功能范围

- API Key 在 Android 侧用 Keystore 加密存储。
- 会话、基础档案、角色卡、世界书、场景、记忆和附件保存在设备本地。
- 支持自动备份、历史归档导入导出、会话包、设定存档、记忆单独导出。
- 历史归档支持合并或替换；导入时校验 ZIP 结构和 CRC。
- 自动备份默认保留最近 5 份，保存到「下载/DeepSeek Replica/自动备份」。备份先写应用内临时文件，核对大小并校验 ZIP 后才发布到下载目录；写入中断或进程被杀不会留下半截文件，每次成功会给出提示。
- 导出的备份不包含 API Key。

#### 使用方式

在设置中启用自动备份，重要会话可另行手动导出。自动备份完成后会提示对话数与「文件已校验」；下载目录仅保留最近 5 份完整 ZIP，历史残留的未完成文件会在下次打开数据页或执行备份时清理。更换设备时，先导出会话包和设定存档，再在新设备导入。历史归档支持合并或替换，导入前应确认提示。可将备份间隔设为 120 分钟；更换设备前应执行“导出所有历史对话”。

#### 限制与注意事项

- 无账号体系，也无中转服务器。数据仅保存在本机，卸载应用会清除本地数据。
- 备份文件可能包含角色卡、聊天记录和图片；对外发送前应检查内容。
- 导出格式有版本差异，跨版本导入不一定百分之百兼容；重要数据保留原始备份。
- 归档导入存在大小和条目限制；较大的会话应提前拆分或保留原始备份。

### 8. 个性化与视觉

#### 功能范围

- 用户资料：设置用户头像和用户名，聊天里显示用户头像与名字，`{{user}}` 也按用户名替换。
- 角色形象：每张角色卡单独设置头像和名字；头像居中裁切、压缩为 256px JPEG，只在本机显示。
- 对话中显示头像：可以关闭；角色头像和用户头像大小分别可调，范围 20–36px。
- 头像形状：圆形或圆角方形。
- 角色内心独白：括号里的内容降低对比度、置灰，并在朗读和语音通话中跳过。
- 主题与气泡：主题色可选经典蓝、青、藤紫、琥珀、玫红、墨绿；气泡圆角紧凑/标准/大圆角；聊天布局卡片/气泡；消息间距紧凑/标准/宽松。
- 字体大小、思考区自动折叠、流式输出自动跟随。
- 设置搜索、会话分组、归档、批量操作。

#### 使用方式

在账号页设置用户头像和名字；在「角色档案与表达」页设置角色基础档案、角色头像、名字、头像大小和形状。需要视觉区分时，可启用“对话中显示头像”并同时显示角色与用户头像；需要节省空间时可关闭。括号独白置灰适用于角色扮演，显示效果更接近内心独白，朗读时会跳过。主题、气泡与间距仅改变外观，可随时切换。

#### 限制与注意事项

- 头像保存在本机，不上传、不进入请求；删除角色卡时对应头像会一起清理。
- 用户名仅用于本地显示和 `{{user}}` 替换，不构成账号体系，也不提供登录功能。
- 个性化设置不随设定存档导出；更换设备后需重新设置外观。基础档案、档案开关、角色卡、卡头像、世界书与场景会随设定存档导出。
- 独白置灰只影响显示和朗读，发给模型的原文不变。
- 低端设备上，复杂主题、长动画和大量图片仍可能导致卡顿；更换主题不能覆盖全部性能问题。

### 9. Token、费用与诊断

#### 功能范围

- 显示每次请求的实际用量、会话统计、缓存命中和未命中。
- 集中列出九个真实会增加消耗的开关：深度思考、智能搜索、世界书注入、长期记忆、场景自动更新、记忆自动提炼、自动压缩、自动标题、上下文提醒。
- 显示峰谷时段提示：高峰时段红色、空闲时段绿色，圆点、文字和浅色边框一起跟随；深色主题使用更亮的红绿。
- 本地 Token 限额：达到阈值提示一次，并在顶栏显示胶囊。
- 显示用量明细开关：回复完成后显示输入、输出、缓存命中、未命中。数字在 100 万以下显示完整整数并带千分位（有小数时保留一位），达到 100 万才缩写成 1M / 1.1M。默认显示在回复上方，可在设置里改为回复下方。
- 请求前缀按缓存友好方式组装：普通对话的 `system` 是默认助手提示；角色上下文只放一张卡、一份完整档案或一条轻量身份行，再拼中性角色基底或自定义提示词。人物优先读取会话绑定，其次读取全局启用卡。记忆、场景与当前轮次世界书作为 `turnContext` 接在当前 user 消息末尾；`latest_reminder` 为独立提醒消息，插入当前 user 之前，不进入 system。因此新增记忆或场景不会改写已发送的 system 和历史。缓存按上游 `usage` 统计，命中与未命中相加等于输入总量。
- 「system 不变」不等于「整个请求前缀不变」：自动压缩会在预算不足时丢弃最旧轮次，开启自动压缩时摘要会插入请求中的首条 user 消息；编辑/删除历史、切分支、修改角色卡或提示词、开关“抑制元叙述”，以及 `latest_reminder` 内容变化（日期、星期、地点、Web、语言），都会改变请求前缀。缓存是否命中仍由上游按实际请求判断。
- 缓存命中与未命中由上游按完整请求前缀判断。首轮冷启动、网关抖动、缓存字段未透传或服务商状态变化均可能导致未命中；该现象不代表 system 丢失，也不代表设定未进入请求。同一会话连续出现异常时，可重新生成或将同一句话重发一次，观察命中是否恢复；仍未恢复时再检查接口、模型和请求日志。
- 记录诊断日志，帮助判断白屏、卡顿、请求失败和权限问题。
- 启动公告说明本次版本的变化和已知边界。

#### 使用方式

长会话前后各检查一次“Token 与费用”页，依次查看请求次数、总输入、缓存命中、未命中与命中率。页面中的开关说明对应实际上下文或请求行为；关闭开关会减少相应上下文或额外请求。诊断日志可用于区分应用卡顿与接口未返回。

#### 限制与注意事项

- 缓存由上游按请求前缀匹配，不按会话 ID 或导入关系匹配。导入长对话后，第一轮仍可能冷启动；从第二轮起，仅在连续使用同一角色卡、同一开关状态且不切换分支时，历史前缀才可能复用。首次未命中时，应先以同一句话重试一次，避免连续修改设定，以便区分冷启动与配置变化。
- 切换深度思考、智能搜索、角色卡或分支，编辑/删除历史，触发自动压缩或预算裁剪，或 `latest_reminder` 内容变化，都会改变请求前缀，命中率会立即下降；该变化来自请求前缀改变，统计本身未出错。同一天内提醒内容通常不变，不会每轮都插一条新消息。
- 这些统计为本地记录，不等同于官方账单。具体口径见下一节。
- 九个开关仅作提醒，不会自动关闭功能；具体取舍由使用者决定。
- 诊断日志可能包含请求元信息；对外提供前应检查是否含 Key、地址或聊天内容。
- 公告只说明当前版本的变化，不构成功能承诺。

### 10. 公告与安全审核

#### 内置公告

- 公告数据在本地，不联网拉取；每个版本首次启动弹一次，设置页“更新公告”可以重新打开。
- 条目按「新增 / 优化 / 修复 / 说明」四类组织，只写改动位置、实际行为和边界，不写营销话术。
- 公告开头集中说明安全审核开关、上下文提醒、导出不含 API Key 和二次创作边界等使用条件。
- 公告不构成功能承诺；项目已停止更新，不存在后续版本。

#### 安全审核 `safety_check`

- 默认开启。开启时请求体携带 `safety_check` 字段，由服务端按平台规则检查并过滤敏感内容；代价是部分表达会被拦下。
- 关闭后请求不再携带该字段，本应用也不再过滤敏感内容；网关或服务商自身的内容审核仍可能存在，以对方规则为准。
- 该开关仅影响本应用附加的字段，不代表模型、网关或平台不再审核。

#### 服务端拒答

- 接口返回拒答时，消息会标记为 `refusal`，界面按拒答处理。
- “保留被拒回复的正文”：开启后保留已经下发的内容，避免整轮变空导致角色断戏。
- “被拒轮次进入上下文”：开启后该轮保留在历史里；关闭则沿用丢弃策略。
- 拒答话术可以自定义；留空使用内置文案。

#### 本地关键词拒答

- 只检查当前用户输入文本，命中任意关键词时立即返回话术，不调用接口。
- 每行一个关键词，或用逗号分隔；可选英文大小写敏感。
- 只做字面匹配，不识别语义、谐音和变体；关键词留空则不拦截；关闭后请求正常发往接口。
- 适用于“自杀、自残”等明确高风险词的本地拦截，不替代完整内容审核。

#### 责任说明

安全审核责任需结合具体情形判断。开启时，判断主要依据服务端规则；关闭时，本应用不再附加该字段，但服务商仍可能审核。责任判断涉及使用者、输入内容、发布或传播行为、平台规则及当地法律，不能仅依据开关状态。仓库仅说明开关行为，不对具体使用行为作合法性背书。

## Token 与用量统计

本节说明 API 用量口径，供首次使用 API 的读者核对统计来源与限制。

### 数据来源

应用本身不计算价格，也不读取使用者的账户余额、积分或额度。页面里的 token 数字来自每次请求返回的 `usage` 字段，例如输入 token、输出 token、缓存命中 token、缓存未命中 token；应用把这些返回值记录在本地，再按会话汇总。

统计规则如下：

- 页面仅显示上游返回的字段；上游未返回缓存字段时，页面不计算命中率。
- 不同网关、不同模型、不同版本的字段名可能不一样；有的只返回总 token，有的不返回缓存明细。
- 本地汇总可能受四舍五入、请求失败重试和流式中断影响，不作为财务凭证。
- 余额、单价、扣费和发票以服务商后台记录为准。本应用不管理余额，也不代表 DeepSeek 官方 API 或任何网关的计费立场。

### 页面字段说明

- **总消耗 / 总输入 / 总输出**：当前会话累计提交与返回的 token 数量，不等同于账单金额。
- **请求次数**：实际发出的请求数量；单次请求可能包含较大的上下文。
- **缓存命中**：上游复用了相同前缀的 token，通常按较低的缓存价格计费。
- **缓存未命中**：本次未被复用的 token，通常按正常输入价格计费。
- **缓存命中率**：一般按“命中 /（命中 + 未命中）”估算。输出 token 通常单列，不计入该分母；具体以页面显示为准。

### 数字显示规则

- 100 万以下显示完整数字并带千分位，例如 `12,345`、`123,456`、`123,456.7`；不再提前缩写成 `12K`、`123K`，避免看不出实际消耗。
- 达到 100 万时才缩写为 `1M`、`1.1M`；100 万整显示 `1M`，110 万显示 `1.1M`。
- 用量明细默认位于回复上方，可在设置中调整为下方。记忆标记始终位于消息末尾，不会被用量明细遮挡。数值仅来自接口返回值，不作本地估算。

### 统计口径与限制

- **分支继承上下文。** 分支在同一条历史主干上分叉，角色卡、世界书、场景、记忆和分叉点之前的对话仍在上下文中。分支仅改变分叉点之后的走向，不会清空此前历史。
- **总 token 与费用不呈线性对应。** 大部分上下文命中缓存时，计费主要来自未命中和新增部分；总 token 较大但命中率较高时，费用可能低于预期。总 token 不大但命中率很低时，几乎全部按输入 token 计费，费用可能上升。评估费用应同时查看总量与命中率。
- **缓存未命中不代表数据错误。** 命中率低通常表示本次请求未复用此前上下文，原因可能包括会话过长、请求前缀改变、世界书或角色卡修改、网关未透传缓存字段，或模型不支持缓存。页面显示上游返回值，不作本地推算。判断费用构成应查看请求次数、未命中 token 和当时启用的功能。

### 成本观察参考

以下为使用经验，不构成官方定价标准。不同模型、网关和账户的单价差异较大，仅供参考。

- **命中率长期在 70% 以上**：通常处于较低增量计费区间，可继续正常使用。
- **命中率在 30%～50%**：单次请求开销上升，长会话应关注余额。
- **命中率低于 20%**：属于高成本区间；即使输入很短，也会提交较长历史。
- **余额变化应结合速度与幅度判断**：连续多轮后余额明显下降，说明单轮成本上升；短消息导致显著扣费时，成本已偏高。
- **连续多轮均出现上述情况**：可保留旧会话，新建会话并复制角色配置，以重置上下文。

分支和重新生成都会继承当前上下文并计入统计，适用于推进同一故事的另一种可能，不适用于零成本重置。隔离上下文、控制成本应新建会话，不应在超长主干上持续分支。

本统计用于查看和分析本地用量，不替代服务商账单，也不构成官方计费解释。金额争议以服务商后台记录为准。

- API Key、签名文件、聊天记录、诊断日志和含个人信息的截图不得提交到公开仓库。此类内容进入 Git 历史后，仅删除文件不会清除记录；发现泄露应立即轮换 Key。
- 安装第三方转发的 APK 前，应核对提交、构建方式和签名来源；来源无法核实时不应安装，也不应填写 Key。
- 使用第三方网关前，应确认其请求与密钥处理方式。

## 构建

前端：

```bash
pnpm install
pnpm type
pnpm build
```

构建产物在 `dist/`。

Android 工程保留在 `android/`，当前配置使用 Gradle 9.7.1、AGP 9.4.0、compileSdk 37、minSdk 29。环境版本不一致时，按实际 SDK 调整 `android/app/build.gradle`：

```bash
cd android
./gradlew assembleDebug
```

仓库不附带 `release.jks`、`debug.keystore` 或任何签名文件。需要发布包时，由发布者生成并保管签名；密钥不得提交到仓库。

应用内的更新检查入口保留为空仓库地址，默认不启用。如需接入自有发布源，填写 `UpdateRelease.java` 中的 `REPOSITORY`。

## 数据与隐私

- 无账号体系，也无中转服务器。API Key 由使用者填写，Android 侧使用 Keystore 加密存储。
- 会话、基础档案、角色卡、世界书、场景、记忆和附件均保存在设备本地。卸载应用会清除本地数据，重要内容应提前导出。
- 请求仅发往使用者配置的接口地址。网关的记录方式不在本仓库控制范围内。
- 导出的备份不包含 API Key；角色卡和设定存档是否含图片，以导出时的提示为准。
